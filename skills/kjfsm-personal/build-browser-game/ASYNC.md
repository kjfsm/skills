# リアルタイムでないゲーム

放置・自動戦闘・ターン制・プレイヤーどうしの売り買いのように、同じ瞬間に同じ場にいなくてよいゲームで、[NETCODE.md](NETCODE.md) と [SLICES.md](SLICES.md) の代わりに読む。部屋・WebSocket・手元の予測は要らない。代わりに、画面を閉じていても進むことと、DO をまたぐ物のやり取りで手戻りが出る。

## 読み替え

- 手順 1 の5つは、意図で読む。「1回の勝負」は1戦闘や1手番で、ここが 20〜40 秒に収まる。「先取」は踏破や完走のような、名前のある区切りに置き換える。「CPU が埋める」は NPC の仲間や NPC の商人で、ひとりでも回る。「決まり方の名前」は1戦闘ごとに付ける
- ひとりでも回る仕組み(NPC)が無いと、人の少ない時間に売り買いも協力も成り立たない。最初の仕様から入れる
- SLICES.md の 1(曳光弾)は、ひとりで1回ぶん遠征して結果が見えるところまで。4(部屋)は要らない。後のチケットの E2E が、その状態へ本物の画面で辿り着ける順に切る。たとえば作成の E2E に素材が要るなら、素材を買えるショップを先に作る。後に回すと、テスト専用の戸を開けて素材を配ることになる

## サーバー

- **進行は時計で回さず、読まれたときに追いつかせる。** DO にタイマーもアラームも持たせず、状態を読まれたとき・操作を受けたときに、その時刻までに終わったぶんを順に確定させてから答える。操作は、先に追いついてから当てる。誰も見ていない DO が起き続けて要求を食わずに済み、追いつきの計算は種と時刻だけで node 層に再現できる
- **1戦闘は、始まった時点で結末まで計算して、時刻つきの出来事の並びにする。** 画面はそれを実時間で再生するだけで、サーバーに押し込む相手がいないので HTTP で足りる。進行中の戦闘には編成の変更が効かず、次の戦闘から効く
- **放置上限は「最後に読まれた時刻 + 上限」まで確定させて止め、次に読まれた時刻から続きを始める。** 向きを逆にすると、上限を超えて戻った人の記録の時刻が後ろへずれる。1回に確定させる数にも上限を置く
- **ログインを持たなくても、持ち物をサーバーが持つなら、推測できないトークンを HttpOnly の Cookie で渡して見分ける。** 他人と物をやり取りするゲームで持ち物を端末に置くと、書き換えた物がそのまま売れる。Cookie は root の middleware の1か所で渡す。他人に見せるのはトークンから導いた公開 ID だけにし、端末を移るための引き継ぎコードを用意する
- **状態はプレイヤーごとの DO に置き、みんなで使う場(市場など)は別の DO にする。** 全員を1つの DO に置くと、1人の長い追いつきが全員の要求を止める
- **保存データの版は、プレイヤーの DO だけでなく場の DO にも持つ。** 版の決まりをプレイヤーのチケットにだけ書くと、場の DO が版を持たずに出て、素材の種類を1つ足しただけで読み込みが落ちる。場の DO は預かりを持つので、版が合わなくても作り直さずに移行する

## DO をまたぐやり取り

- **頼む前に自分の持ち物から引いて保存し、頼みが断られるか届かなければ戻す。** 引く前に頼むと、返事を待つ間に届いた別の操作が同じ物を使える。戻すときは、await の前に取った写しではなく、最新の状態に差分を当てる
- **預かりは場の DO が持つ。** 注文を出すときに物やお金を預かり、取り消しで返す。約定した相手の分は、相手の受け取りに積む
- **受け取りは番号で2段に分けて消す。** 場の DO は受け取りを増えていく番号で積む。プレイヤーの DO は、入れ終えた最大の番号を状態と同じ値に保存して、それより大きい番号だけを足す。場の DO は、プレイヤーが次の引き取りで伝えてきた番号以下だけを消す。消すのと足すのを1回でやると、途中でどちらかが落ちたときに、二重に入るか消える
- **プレイヤーの状態を作り直すなら、場の DO の側も合わせる。** 作り直した状態が番号 0 から引き取ると、旧い状態で入れ終えた受け取りがもう一度入り、旧い注文が件数の上限に数えられ続ける
- **手数料を約定ごとに切り上げるなら、「値段 × (1 − 率) > 別の売り先の値段」で振り分けない。** 1個だけ約定したときの手取りが、別の売り先と同じになる。1個で約定したときの手取りで比べる
- **場の刻み(NPC の値付けやニュース)の乱数は、刻みの通し番号だけから作る。** 読まれるたびに前回から今までの刻みを進めるので、同じ刻みを何度計算しても同じ値になる必要がある

## 画面

- **サーバーの時刻との差を覚え、戦闘が終わる時刻を過ぎたら1回だけ読み直す。** 一定間隔のポーリングにしない。裏のタブにいる間の読み直しは、表に戻るまで待たせる
- **応答は、要求を出した順に当てる。** 読み直しと操作の応答が逆順に届くと、あとから届いた古い状態が操作の結果を消す。要求に通し番号を振り、古い番号の応答を捨てる
- **追いつき中(確定させる数の上限で止まっている間)は、操作のボタンを押せなくし、短い間隔で読み直す。** 操作は先に追いつくことが前提なので、その間の操作はサーバーが断る
- **「直前の戦闘」は、最後に確定した戦闘から取り直す。** 見ていない間に何戦も確定したとき、または呼び戻したときに、画面が最後に再生した古い戦闘を残すと、結果と食い違う
- 演出は、今の時刻の直前の出来事からだけ作る。裏のタブから戻ったときに、溜まった演出を一度に出さない(NETCODE.md の「画面」と同じ)
