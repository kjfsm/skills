# 実装する

ユーザーがスペックやチケットで記述した作業を実装する。引数でチケットやスペックの参照が渡された場合は、それが実装対象である。

可能な場所では、事前に合意したシームで /tdd を使う。

作るものに見た目・レイアウト・アニメーションが含まれるなら、/verifying-visual-work を使う。テストで押さえられない部分の規律 — 名前の付いた技法なら書き始める前に参照を1つ読む、座標が絡むなら不変量を式にして実測と突き合わせる、最初の1画面ではなく複数の状態で見る — をそこが持っている。

実装している間は、安いゲートだけを頻繁に回す — 型チェックと、いま触っているテストファイル。通しの検証は最後に一度だけである。

作業が完了したと思ったら /verification-loop でクリーンランを取る。

クリーンランが取れたら /two-axis-review を使って作業をレビューする。

作業を現在のブランチにコミットする。
