# ビートで書く

<what-to-do>

ユーザーは素材のマークダウンファイルを渡した(あるいはこれから渡す)。これは **exploit** である: 探索は終わっており、素材の山は固定されている — その中を通る道筋にコミットし、各ビートを埋めるために山を採掘する。

ユーザーが記事の保存先を指定していない場合は、一度だけ尋ねてそのパスを覚えておく。

その後、選択式アドベンチャー風に、ビートごとの旅を進める:

1. **前提条件を確立する。** どのビートよりも前に、読者が最初から持ち込んでいる知識 — 最初から**接地**している概念 — をユーザーと決める。それ以外はすべて、後のビートが使う前に、いずれかのビートによって接地されなければならない。[接地](#接地)を参照。
2. 素材から引いた2〜3個の候補となる**起点のビート**を書く。それぞれが記事への異なる入り口である。それぞれは接地済みの概念にしか頼れない。それぞれがどの新しい概念を接地するかを書き留める。記事ファイルに書き込む前に、これらのビートをユーザーに見せる。ユーザーが1つを選ぶ。その選択によって解放されるビートをプレビューする — ユーザーが少し先の道筋を見ているかのように。
3. ユーザーが起点のビートを選んだら、**そのビートだけ**を記事ファイルに書き込む。ビートは1文のこともあれば、数段落のこともある — そのビートが自然にそうなる形でよい。そこで止める。
4. 記事ファイルをディスクから再読み込みする。その後、2〜3個の候補となる**次のビート** — 記事が今立っている地点から旅が転換しうる異なる方向 — を提示する。それぞれが現在の接地済み集合から到達可能でなければならない。それぞれが何を接地するかを書き留める。
5. 記事が自然な終わりに達するまで、ステップ3〜5を繰り返す。

</what-to-do>

## 接地

すべての**概念**は、あるビートがそれに頼る前に**接地**されていなければならない: 読者が最初から知っているか、それより前のビートでそれに出会っているかのどちらかである。接地されていない概念に手を伸ばすビートは読者を置き去りにする — それはこの旅が絶対にしてはならない一手である。単位は概念であり、それを表す言葉ではない: ビートは、専門用語が一切見当たらなくても、読者が持っていない考えに頼ることがありうる。概念に名前 — **用語** — がある場合、それを接地するとは、考えと用語を同時に着地させることを意味する。

概念は次の2通りのいずれかで接地される:

- **前提条件** — 最初のビートより前に接地されている。読者がそれを持ち込む。冒頭で固定される。
- **導入済み** — あるビートがそれを確立し、それ以降のすべてのビートにとって接地済みとなる。

したがって各ビートは2つの仕事をする: すでに接地済みの概念を**要求**し、新しい概念を**接地**する。ここまでに接地済みのものの一覧を常に保ち、ビートが着地するたびに更新する。

これが選択式アドベンチャーを形作るものである。候補となるビートは、それが要求するものがすべてすでに接地済みである場合にのみ到達可能である。概念 X を接地するビートを選ぶと、X を待っていたすべてのビートが解放される。次のビートを提示するときは、それらすべてが現在の接地済み集合から到達可能でなければならない — そして、それぞれが何を接地するかを述べ、ユーザーがどの道筋が開くかを見られるようにする。

大きなレバーは、何を前提条件にし、何を作品の中で接地するかである。冒頭で要求しすぎると、それを持たない読者を締め出してしまう。中で接地しすぎると、序盤のビートが定義だらけになる。前提条件を確立する際にこれをユーザーと決め、魅力的なビートがまだ誰も接地していない概念を必要とすると判明するたびに見直す — 解決策は、その前に接地用のビートを置くか、その概念を前提条件に昇格させるかのいずれかである。

## ビートとは何か

ビートは旅の中の一手である。それは1つのことをする — 場面を設定する、論点を着地させる、問いを投げる、余談を挟む、視点をひねる。そして止まり、次のビートが転換できる場所に読者を残す。

ビートの大きさは、それが必要とするものによって決まる:

- その一手がそれだけなら1文で十分(「そして三週間、何も起こらなかった。」)。
- 一手に前置きが必要なら短い段落。
- ビートがそれ自体で完結した挿話、論証、事例であれば複数段落。

もし「ビート」が5段落と3つの小見出しを必要とするなら、それはビートではなく — 2つのビートが糊付けされたものである。分割すること。

## 山から引き出す

各ビートを満たすために、素材の山から材料を引き出す。言い換え、分割、再構成、引用のいずれでもよい。山は採石場である。

## 旅の終わり

記事は旅が完結したときに終わる — 山が空になったときではない。ほとんどの山には、収まりきらなかった断片が残る。それは問題ない。それこそが、必要以上の素材を用意しておく意味である。

## 執筆のリズム

- 一度に1つのビートだけを追記する。決して先回りして書かない。
- 書き込むたびに、その前に記事ファイルをディスクから再読み込みする。ユーザーの編集は絶対に保持する。
- ユーザーが以前のビートを大きく編集した場合は、それが次に来るものを変えるままにする。
- ユーザーが「そのビートを書き直して」や「戻ってビート3を別のものにして」と言ったら、そうする — その場で編集し、他はそのままにする。
