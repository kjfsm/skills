# Wizard

**ウィザード**とは、手作業でやるには面倒で、毎回 AI に説明し直すのも面倒な手作業の手順を、人間にステップバイステップで案内する bash スクリプトである。各 URL を開き、何をクリックしコピーすべきかを正確に伝え、値を取得し、それらを本来あるべき場所(`.env`、GitHub のシークレット)に書き込み、各ステージで確認を取り、残りどれくらいかを示す。サードパーティサービスの設定、一回限りの移行の実行、あるいはプロジェクトをある状態から別の状態へ移すために使われることもある。

心地よい UX はすでに [template.sh](template.sh) によって解決済みである — 残り時間つきの進捗表示、確認ゲート、クロスプラットフォームな URL オープン(WSL 含む)、隠された状態でのシークレット入力、冪等な `.env` の upsert、`gh secret`/`gh variable` への書き込み、締めのサマリー。**あなたの仕事は手順のスコープを定め、そのステージを執筆することだけである。** `STAGES` マーカーより上のライブラリはどのウィザードでも同一であり、その一貫性こそが重要な点である — 決して手で編集しないこと。

ウィザードはデフォルトでは使い捨てである — 一回の実行のために作られ、scratch か `scripts/` パスに保存され、作業が終われば削除される。リポジトリに残すべき再現可能なセットアップ手順をユーザーが望む場合にのみコミットする。

## プロセス

### 1. 手順のスコープを定める

人間が取るべきすべての手作業ステップと、その過程で取得されるすべての値を洗い出す。まずリポジトリを読むこと — いきなり尋ねてはいけない:

- セットアップの場合: `.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、フレームワークの設定、`.github/workflows/*`(すべての `secrets.*` / `vars.*` 参照は、ウィザードが生成すべき値である)。
- 移行や遷移の場合: 現在の状態、目標の状態、その間にある不可逆なアクション。

その後、ステージの順序付きリストと各ステージが生成する値をユーザーに見せて確認する — ユーザーは追加・削除・並べ替えができる。

**完了の条件:** すべてのステージが順序どおりに名付けられており、取得する各値について (a) 人間がどこでそれを得るか、(b) どこに書き込まれるか(`.env`、GitHub のシークレット、両方、あるいはどこにも書かれない — 純粋なアクションのステージもある)、(c) それが秘密(隠し入力)か公開かがわかっていること。

### 2. 各ステージの経路をマッピングする

各ステージについて、人間がたどる正確な経路を書く: どの URL を開くか、そこで何をするか、値がどこに表示されるか、どの変数を埋めるか — 例:「ダッシュボード → Developers → API keys → Reveal test key → コピー」。現在の UI や正確なコマンドを実際には知らない箇所は、そう明言してユーザーに尋ねるかドキュメントを確認する — 存在するかどうかわからないステップを創作してはならない。

**完了の条件:** すべてのステージが、見知らぬ人でも従える具体的な指示にまで落とし込まれていること。

### 3. ウィザードを執筆する

`template.sh` を目的のパスにコピーする。サンプルステージを、依存順に並んだステップごとの `stage` に置き換える。ライブラリのヘルパー — `stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm` — を使い、`TOTAL_STAGES` と `TOTAL_MINUTES` に正直な見積もりを設定する(これが残り時間表示を駆動する)。

テンプレートが定める基準を守ること: 値を尋ねる前に URL を開く、秘密の値には `ask_secret` を使う、永続化するすべての値を `write_env` する、CI が実際に必要とする値だけを `set_secret` する、不可逆なアクションの前には `confirm` する。各 `stage` は画面をクリアして現在のステップだけが見えるようにする — 人間がスクロールで見失わないよう、1ステージにつき1つの作業に絞ること。マーカーより上のライブラリには触れないこと。

### 4. 検証して引き渡す

- `bash -n <script>`; 利用可能なら `shellcheck` を実行する。
- `chmod +x <script>`。
- 自分でエンドツーエンドに実行してはいけない — ブラウザを開き、人間の入力待ちでブロックするため。代わりに静的にトレースする: ステップ1で挙げたすべての値が取得され、ステップ1で述べた場所に収まっているか、そしてすべての `set_secret` の名前が CI 内の `secrets.*` 参照と正確に一致しているかを確認する。
- 実行方法をユーザーに伝える。再現可能なセットアップ手順であれば、コミットして README からリンクし、次の人が AI に尋ねるのではなくスクリプトを実行できるようにする。
