# セッションを閉じる

入力待ちのまま tmux に残ったセッションは、立てた開発サーバーを抱えたまま誰にも思い出されない。並べたセッションのぶんだけ溜まるとメモリが尽き、tmux ごと全部が落ちる。外から `tmux kill-session` で閉じても片付かない — `run_in_background` で立てたサーバーはペインとは別のプロセスグループにいて、生き残る。何を立てたか知っている自分が止めてから、自分で閉じる。

## 1. 閉じてよいか確かめる

```bash
git status --porcelain
git log --oneline @{u}..HEAD 2>/dev/null || git log --oneline origin/HEAD..HEAD
```

未コミットか未 push が1つでもあれば **閉じずに止まり**、何が残っているかを伝える。worktree は閉じても残るが、次に誰がそれを拾うのかは誰も覚えていない。

PR が開いたまま・レビュー待ちなのは止める理由にならない — 会話は `claude --resume` で戻せる。

## 2. 自分が立てたものを止める

- **バックグラウンドのタスク** — 自分が `run_in_background` で立てたものを `TaskStop` で1本ずつ止める。
- **開発サーバー** — ポートを覚えていなくても、作業ディレクトリで引ける。LISTEN しているプロセスのうち、cwd がこのチェックアウトの中にあるものが自分のものである:

  ```bash
  root=$(git rev-parse --show-toplevel)
  for pid in $(ss -lptnH | grep -oP 'pid=\K[0-9]+' | sort -u); do
    cwd=$(readlink "/proc/$pid/cwd") || continue
    case "$cwd" in "$root/.claude/worktrees/"*) continue ;; "$root"|"$root/"*) ps -o pid=,args= -p "$pid"; kill "$pid" ;; esac
  done
  ```

  `.claude/worktrees/` を外すのは、本体のチェックアウトで動いているとき、その下にある **別のセッションの worktree** のサーバーまで巻き込むからである。`pkill -f` のようなパターン一致を使わない理由は `/kjfsm-skills:verification-loop` の「観測する」にある。

止めたら同じループをもう一度回し、何も出ないことを確かめる。

## 3. 報告して閉じる

先に報告を書く: 止めたもの、PR の番号と状態、worktree のブランチ。**そのあと、同じ返答の最後の操作として** ペインを閉じる:

```bash
setsid nohup sh -c "sleep 30; tmux kill-pane -t '$TMUX_PANE'" >/dev/null 2>&1 &
```

- **遅らせるのは、報告を書き終えるためである。** 即座に閉じると、返答の途中でプロセスごと消える。予約を先に走らせてしまっても、30 秒あれば報告は書き終わる — 5 秒では、長い報告が途中で切れうる。`setsid` はセッションの終了に巻き込まれないようにするため。
- **閉じるのはペインで、セッションではない。** `claude -w --tmux` が立てたセッションならペインは1枚なので、セッションごと消える。ユーザーが同じセッションに別のウィンドウを開いていても、それは残る。
- **`$TMUX_PANE` が空なら tmux の中ではない** — 自分では閉じられないので、報告の最後に `/exit` で閉じられると伝える。

完了基準: 1. で何も残っていないことを確かめ、2. のループが何も返さず、報告のあとにペインを閉じる操作を走らせた。止まったなら、何が残っていて止まったのかを報告している。
