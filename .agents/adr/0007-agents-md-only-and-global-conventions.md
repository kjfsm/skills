# 本体は `AGENTS.md` だけにし、ユーザーのグローバルにある規約はリポジトリへ写さない

`setup-skills` の手順4は、本体を `AGENTS.md` に置き、`CLAUDE.md` を `@AGENTS.md` の1行にする形を敷いてきた。そして `### Conventions` と `setup-rules` の絶対ルール・自己更新ルールを、リポジトリごとに本文として書き込んできた。この2つを改める。

## 1. `CLAUDE.md` を置かない

import の1行を置いた理由は、Claude Code が `AGENTS.md` を直接読まないセッションがあったことである — v2.1.277 未満、フィーチャーフラグを取得しないセッション、インストール直後の初回。公式ドキュメント([memory](https://code.claude.com/docs/en/memory)、2026-10 時点)の現状はこうなっている:

- v2.1.277 以降、作業ディレクトリとその上に `CLAUDE.md`・`.claude/CLAUDE.md`・`CLAUDE.local.md` のどれも無ければ `AGENTS.md` を直接読む。ユーザーの `~/.claude/CLAUDE.md` と `.claude/rules/` は判定に数えず、並んで読まれる
- v2.1.281 で、Bedrock やテレメトリ無効のセッションが読めなかった問題が解消した
- 読めない例外は3つだけ: v2.1.277 未満、`/plugin` で組み込みプラグインを無効化した、v2.1.276 以前から上げた直後の初回セッション(次から読む)
- 公式は「`@AGENTS.md` しか持たない `CLAUDE.md` は消してよい。直接読めないセッションがあるなら残す」としている

1行の `CLAUDE.md` は、それ自体が「`AGENTS.md` を読ませなくする」条件である。置けば import を保守し続け、誰かが下に1行足した日に Claude Code だけが別の指示を読む。**`CLAUDE.md` は置かず、例外に当たる人がいるリポジトリだけ1行を残す。** `CLAUDE.local.md` を使う人も例外に入る — あると `AGENTS.md` が読まれなくなるからである(代わりに **Project instructions** を `claude-md-and-agents-md` にしてもよい)。

このリポジトリ自身も `CLAUDE.md` を消し、検査 19. の向きを「1行であること」から「無いこと」に変える。

## 2. グローバルにある規約をリポジトリへ写さない

`### Conventions` の本文はサブエージェントにも届かせるために常駐させている(ADR 0004)。届かせる経路はリポジトリの本体だけではない — ユーザーの `~/.claude/CLAUDE.md` も、そのユーザーのどのリポジトリのセッションにもサブエージェントにも読まれる。同じ本文を自分の全リポジトリに置いていたユーザーが、それをグローバルへ1部にまとめた。そのうえで `setup-skills` が従来どおり書き込むと、新しいリポジトリを作るたびに写しが1つ増え、片方だけ直った日に嘘をつく。

**`setup-skills` と `setup-rules` は書く前に `~/.claude/CLAUDE.md` を読み、同じ本文・同じ項目があればリポジトリには書かない。** 置くのはリポジトリ固有の具体値(デフォルトブランチ名、生成物の rule の場所、シークレットのファイル名)だけである。グローバルに無ければ従来どおり書く — このプラグインはグローバルを持たない人にも配る。

ユーザーのグローバルの写しは配布物ではないので、AGENTS.md が言う「3か所」に数えず、`render.py` も写さない。ずれたらそれはユーザーのファイルの手入れ(`tend-memory-files`)の範囲である。

## 却下: グローバルに任せる判断を黙って下す

`~` はクラウドセッションと他人のクローンには持ち越されない。グローバルにあるからと省いたリポジトリは、そこでは規約が無い状態で動く。どちらを取るかはリポジトリの使われ方で決まり、スキルからは見えない。**書く前にユーザーに訊く**(`setup-skills` 手順3、`setup-rules` 手順2)。

## 却下: グローバルを4か所目の同期先にする

`render.py` が `~/.claude/CLAUDE.md` にも写せば、ずれは起きない。だが配布物がインストール先のユーザーのファイルを書き換えることになり、`force-for-plugin` を付けない理由(入れた人の設定を黙って上書きしない)と同じ理由で採らない。

## 覆る条件

- Claude Code が `CLAUDE.md` と `AGENTS.md` を既定で両方読むようになったら、1. の例外の列挙は要らなくなる
- クラウドセッションが `~/.claude/CLAUDE.md` を持ち越すようになったら、2. の「訊く」は要らなくなる
