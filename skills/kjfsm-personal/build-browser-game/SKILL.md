# ブラウザゲームを作る

**kjfsm のメインフロー(`/kjfsm-skills:ask-kjfsm`)に沿って、7つの手順で進める。** このスキルが足すのは、各段でゲームに固有のことと、作ったあとで手戻りになりやすいものである。細部は次のファイルにある。

- [SLICES.md](SLICES.md) — チケットの切り方と、各チケットで守ること
- [NETCODE.md](NETCODE.md) — 部屋の DO と画面の通信
- [DEPLOY.md](DEPLOY.md) — 本番に出す順
- [ACCOUNT.md](ACCOUNT.md) — ログインとランキング。手順 1 で入れると決めたときだけ読み、以後の手順にそこに書いた分を足す

手順 1〜4 は1つの途切れないコンテキストで進め、そのあとはチケットごとにコンテキストを空ける。`to-spec`・`to-tickets`・`implement-and-review` はユーザー呼び出し型でモデルからは呼べない。ユーザーに打ってもらうか、その本文(プラグインの SKILL.md)を読んで同じ手順を踏む。

## 1. 何を作るか決める

面白さは作ったあとからは足しにくい。次の5つを満たす案を選ぶ。

- 縦持ちのスマホで、片手の親指で動き、もう片手で1つのボタン
- 1回の勝負が 20〜40 秒で、負けてもすぐ次が始まる
- 先取(例: 3勝)で一区切りがつく。勝負を繰り返すだけでは、どこでやめても同じで、遊ぶ目当てが無い
- ひとりでも遊べる(人が足りなければ CPU が埋める)。友だちとは合言葉の部屋で遊び、そこでは CPU を外して1対1もできる
- 決着の瞬間に、決まり方の名前が付く。演出と実況の種になる

ログインとランキングを入れるかも、ここでゲーム性から決める。通算の成績を競うことが遊ぶ目当てになるなら入れ、一区切りごとの優勝で足りるなら入れない。入れると、ログインの手間と、IdP・共有 D1 の維持がついてくる。遊んだユーザーが、入れたものを不要と判断して外すこともある。

ユーザーが「任せる」と言っていれば自分で決める。ユーザーが自分で決めたいなら、土台を起こしたあとに `/mattpocock-skills:grill-with-docs` で詰める。決めた語は `CONTEXT.md` に置く。

完了基準: 遊び方を1文で言えて、5つとも満たし、ログインとランキングの有無が決まった。

## 2. 土台を起こす

`cf-workers-full-stack-template` から起こす。手順はテンプレートの README「フォークしたら」にある。`/kjfsm-skills:setup-repo` が敷くもの(検証ゲート・rules・CI・lefthook・イシュートラッカー)と、kjfsm-auth の RP・共有 D1 の相乗りがそろっている。README に無いことは次のとおり。

- 写す前に `git fetch` し、`git archive origin/main | tar -x -C <新しいリポジトリ>` で写す。手元の clone は古いことがある
- テンプレートが `kjfsm/cf-workers-full-stack-template#11` より前の版なら、README の置き換えは `git grep` ではなく `grep -r --exclude-dir=node_modules` で探し、`check:migrations` を #11 の `existsAt` の形に直す。写した直後のファイルは未追跡で `git grep` に拾われず、origin/main に無い `wrangler.jsonc` で `git show` が落ちる
- 手元のポートは `grep -rhoE 'port: ?[0-9]{4}' ~/github/kjfsm/*/vite.config.ts` で空きを探す
- `.gitignore` に `.claude/worktrees/` を足す。テンプレートには無く、本体のチェックアウトで worktree が未追跡に出る
- ログインを入れないなら、RP・D1・開発用の入口をここで外す。残すと、使わない secret と共有 D1 の相乗りが、本番に出す前提として残る

完了基準: 名前・slug・ポートを置き換え、テンプレートの検証ゲートが緑のままコミットした。

## 3. 仕様にする — `/mattpocock-skills:to-spec`

次の決定は、公開したあとやレビューで直すことになりやすい。最初から仕様に入れる。ログインを入れるなら、ACCOUNT.md の「仕様」も足す。

- 決着は、残りが1つになった瞬間に決める。手柄は、そのとき場に残っている相手につける
- 途中で抜けた人は負けとして載せる。勝ちが決まったあとに抜けた勝者は勝ちのまま
- 先取で優勝が決まったら、ふだんの結果より長く見せ、全員の勝ち数を 0 に戻して次へ進む。公開の部屋では、誰かの操作を待たずに進める
- 合言葉の部屋では、CPU を外せる
- 本番は、main にマージしたあと人間が繋ぐ Workers Builds が出す

テストのシームは4つある。勝負の計算は node 層、部屋の DO は bindings 層で WebSocket を張り、ページは http 層、画面は E2E と Playwright で3台を駆動する観測で撃つ。

完了基準: 仕様がイシューとして出て、上の決定とシームが載っている。

## 4. チケットに分ける — `/mattpocock-skills:to-tickets`

[SLICES.md](SLICES.md) の切り方を叩き台にする。最初は、ひとりで CPU と1勝負できる曳光弾。

完了基準: チケットがブロッキングエッジ付きで出た。

## 5. チケットごとに作る — `/kjfsm-skills:implement-and-review`

ブロッカーの片付いたチケットから1本ずつ作る。各チケットで守ることと完了基準は、[SLICES.md](SLICES.md) の同じ番号の節にある。

完了基準: 本番に出すチケットを残して、すべての PR がマージされた。

## 6. 全体を二軸レビューする — `/kjfsm-skills:two-axis-review`

基点はテンプレートから起こしたコミット、スペックはユーザーの依頼文と手順 3 の仕様。チケットごとのレビューでは、ファイルをまたぐずれや、あとのチケットが先の約束を崩したものが見えない。

完了基準: 両軸の指摘を直したか、直さない理由を持った。

## 7. 本番に出す

**エージェントは本番へ手でデプロイしない。** 本番は main への push を受けた Workers Builds が出し、その連携はマージのあと人間が繋ぐ。順序は [DEPLOY.md](DEPLOY.md) にある。人間の手順は `/mattpocock-skills:wizard` で台本にしてよい。

完了基準: DEPLOY.md の完了基準をすべて満たした。
