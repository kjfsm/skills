# セッションを閉じる

入力待ちのまま残ったバックグラウンドセッションは、立てた開発サーバーを抱えたまま誰にも思い出されない。並べたセッションのぶんだけ溜まるとメモリが尽き、全部が落ちる。外から `claude stop` で止めても片付かない — `run_in_background` で立てたサーバーは次のプロセスへ引き継ぐために残され、ポートを握ったまま生き残る(`claude rm` なら一緒に止まる)。何を立てたか知っている自分が止めてから、止めてよいと報告する。

## 1. 閉じてよいか確かめる

```bash
git status --porcelain
git log --oneline @{u}..HEAD 2>/dev/null || git log --oneline origin/HEAD..HEAD
```

未コミットか未 push が1つでもあれば **閉じずに止まり**、何が残っているかを伝える。worktree は閉じても残るが、次に誰がそれを拾うのかは誰も覚えていない。

PR が開いたまま・レビュー待ちなのは止める理由にならない — 会話は `claude --resume` で戻せる。

## 2. 自分が立てたものを止める

- **バックグラウンドのタスク** — 自分が `run_in_background` で立てたものを `TaskStop` で1本ずつ止める。
- **開発サーバー** — ポートを覚えていなくても、作業ディレクトリで引ける。LISTEN しているプロセスのうち、cwd がこのチェックアウトの中にあるものが自分のものである:

  ```bash
  root=$(git rev-parse --show-toplevel)
  for pid in $(ss -lptnH | grep -oP 'pid=\K[0-9]+' | sort -u); do
    cwd=$(readlink "/proc/$pid/cwd") || continue
    case "$cwd" in "$root/.claude/worktrees/"*) continue ;; "$root"|"$root/"*) ps -o pid=,args= -p "$pid"; kill "$pid" ;; esac
  done
  ```

  `.claude/worktrees/` を外すのは、本体のチェックアウトで動いているとき、その下にある **別のセッションの worktree** のサーバーまで巻き込むからである。`pkill -f` のようなパターン一致を使わない理由は `/kjfsm-skills:verification-loop` の「観測する」にある。

止めたら同じループをもう一度回し、何も出ないことを確かめる。

## 3. 報告する

報告に書くのは、止めたもの、PR の番号と状態、worktree のブランチ、そして自分の ID(`${CLAUDE_CODE_SESSION_ID:0:8}`)である。

セッションを止めるのは自分ではなく、報告を受けた側である。自分の ID に `claude stop` を遅らせて仕掛けるような、自分を外から止めるプロセスは残さない — 報告を書き終える前に止まるか、止まらずに孤児になるかのどちらかで、確かめる者がいない。

- **立てた側から `SendMessage` で頼まれた** → 報告をその相手へ `SendMessage` で返す。止めるのは相手である。
- **ユーザーに言われた** → 報告の最後に `claude rm <自分の ID>` の行を添える。会話を残してあとで戻るなら `claude stop <自分の ID>` でもよい — 2. で止めてあるので、サーバーは残らない。`claude agents` の一覧からも止められる。バックグラウンドセッションでなければ(`claude agents --json` で自分の行の `kind` が `background` でない)、`/exit` で閉じられると伝える。

完了基準: 1. で何も残っていないことを確かめ、2. のループが何も返さず、止め方を添えて報告した。止まったなら、何が残っていて止まったのかを報告している。
