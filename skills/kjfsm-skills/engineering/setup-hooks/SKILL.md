# 弾く層を敷く

`CLAUDE.md` と `.claude/rules/` は**読まれることを期待する**層である。読まれれば効くが、読まれたかどうかは観測できない。機構はハーネスや git が実行するので、**モデルが何を読んだかと無関係に効く**。

`/kjfsm-skills:setup-rules` が敷く自己更新ルールの3段目がここに当たる — 1. パス固有の事実は rules、2. 手順は skills、**3. 決定的に弾きたい挙動はここ**。

**ただし機構は Claude Code のフックのことではない。3層ある。**

これはプロンプト駆動のスキルであり、決定的なスクリプトではない。探索し、見つけたものを提示し、ユーザーと確認し、それから書く。

## 層は「何から見えるか」で決まる

議論ではなく構造で決まる。1つの検査が置ける層は、たいてい1つしかない。

| 層                                                | 届く相手                                     | 構造的に見えないもの                                                            |
| ------------------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------- |
| `.claude/settings.json` の `permissions.deny`     | Claude が**名指ししたパス**(Bash の中も含む) | **名指ししない読み書き**(`grep -r`、`pnpm install` による lock の書き換え)      |
| `scripts/check-*.ts` ← git hook + CI + 検証ゲート | 人間・モデル・手元・クローン・CI のすべて    | **gitignore 済みのファイル** — staged にならないので git からは原理的に見えない |
| `.claude/hooks/*.sh`(Claude Code のフック)        | そのマシンの Claude セッションだけ           | クローンにも CI にも人間にも届かない                                            |

**上から順に試す。** 下ほど効く範囲が狭く、書く量が多く、**壊れても誰も気づかない**。

3層目に残ってよいのは、上2つから構造的に見えないものだけである。

- **コマンドの形でしか判定できない書き込み** — `pnpm install` による lock の書き換えのように、引数にパスが出てこないもの
- **git hook 自身を飛ばすフラグ**(`--no-verify`)— git hook に入れるのは自己言及で、原理的に不可能
- **モデルへの働きかけ** — 促し、注意の喚起。git hook はモデルに話しかけられない

これ以外が3層目に残っているなら、移し損ねである。**「フックだけが持っている検査」は、クローンでも CI でも効いていない。**

## 何を機構にするか

**4つすべてを満たすものだけ**を落とす。1つでも欠けたら散文のままにする。

1. **すでに散文で書いてあり、実際に破られた。** 先回りしない。破られていないルールに機構を足すと、コストだけが残る
2. **破られたことに気づけない、または戻すのが高い。** 型エラーや落ちるテストが教えてくれるものには要らない — 生成物の手編集(次の再生成で黙って消える)、シークレットのコミット、適用済みマイグレーションの改変が典型
3. **ツールの入力かリポジトリの状態だけで機械的に判定できる。** パスの glob、コマンドの接頭辞、`git diff` の結果。**「適切か」を判断する必要があるなら機構にはできない** — 判断はモデルの側にしか無い
4. **実態を数えた。** 「規約に書いてある」は根拠にならない。`git log --first-parent` で PR 経由率を数える、`git log -p` で手編集の痕跡を探す。規約と実態が食い違っているなら、**先に決めるのはどちらが正かであって、機構ではない**

**通ってよい操作を1つでも止める検査は、無いより悪い。** 止められたモデルは目的を捨てず、別の経路を探す — 生成し直すコマンドが書いていなければ、生成物を消してから同名で書き直す。回避されたぶんだけ、ルールは守られたように見えて実際は緩む。

⚠️ **回避手順がドキュメントに書かれていたら、その検査は厳しすぎる。** 「`rm` してから同名で `Write` する」のような行を見つけたら、それは述語を直す合図である。回避手順を書き足す場面ではない。

## 手順

### 1. 探索する

- `CLAUDE.md` / `.claude/rules/` — **すでに書いてある**禁止事項。ここに無いものはまだ候補ではない
- `git log` — 実際に破られた痕跡と、条件4の数。生成物の手編集を戻すコミット、revert
- `.gitignore` と生成物の実パス、それぞれの再生成コマンド
- `lefthook.yml` / `.husky/` / `package.json` の `simple-git-hooks` — git hook の層がすでにあるか
- `.claude/settings.json` — 既存の `permissions` と `hooks`。あるならマージであって新規作成ではない
- `.github/workflows/` と `docs/agents/verification.md` — 同じ述語がすでに CI 側にあるか
- インストール済みのスキル — git の破壊的コマンドだけが目的なら `/git-guardrails-claude-code` が完成品を持っている

**既存のフックを1本ずつ、何が見えているかで数え直す。** CI にも検証ゲートにも同じ述語が無いフックは、**手元の Claude セッションの中でしか効いていない**。それが意図どおりかを、移す前に確かめる。

### 2. 候補を挙げ、層を割り当て、確認する

候補ごとに、上の4条件と**行き先の層**を1行ずつ埋める。埋まらないものは落とす。埋まったものを一覧でユーザーに見せ、確認を取ってから書く。

層は上の表で機械的に決まる。迷うのは「どちらからも見える」ときだけで、そのときは**広いほう**(上の表で下の行)を採る。

### 3. `permissions.deny` に書けるものを書く

パスの保護はここで終わる。スクリプトは0本でよい。

- **`deny` は Bash の中も見る。** リダイレクトの先(`> .env`)と、名指しされたファイルコマンド(`cat`、`sed`、`tee`)の引数は、同じ規則で判定される。**取り逃すのはパスを名指ししない読み書き**である — `grep -r pattern .`、`pnpm install` による lock の書き換え、スクリプトが自分で開くファイル
- **参照されるのは `Read(...)` と `Edit(...)` だけ。** `Write(...)` のパス付きルールは受理されたうえで**一度も見られない**。`Read` の deny は同じパスへの `Edit` と `Write` も塞ぐ
- **glob が巻き込む先は `!` の否定で抜く。** `Read(./.dev.vars.*)` の後ろに `Read(!.dev.vars.example)` を置く。⚠️ **抜きたい規則より後ろに置いたときだけ効き、同じ設定ファイルの中にしか届かない**
- **素の名前(`"NotebookEdit"`)を書くとツール定義がペイロードから消える** — 詳細は `/kjfsm-skills:tend-memory-files`

### 4. 述語を1本のスクリプトに置き、両方から呼ぶ

git に届くものの検査は、**述語を `scripts/check-<何>.ts` に1本置き、そこから手元と CI の両方へ配る**。

```
scripts/check-*.ts       ← 述語は1か所。ユニットテストで撃てる
docs/agents/verification.md → pnpm check   ← 検証ゲートに畳む
lefthook.yml             ← 薄い呼び出し役。pre-commit は1秒未満、重いものは pre-push
.github/workflows/       ← 同じコマンドを呼ぶ(`/kjfsm-skills:setup-ci`)
```

書くときの規律は4つ。

**述語は存在ではなく差分で書く。** 「そのファイルがあるか」は、生成直後の正当な手直しまで弾く。`origin/<既定ブランチ>` から分岐した地点との差分を基点にすると、まだ push していないものは通り、**すでに共有されたものの改変だけ**が落ちる。CI 側の checkout は `fetch-depth: 0` が要る — 既定の 1 では merge-base が解決できず、検査が**黙って飛ぶ**。

⚠️ **全件を走査する述語は、該当ファイルが0本のあいだ黙っている。** 1本入った日に初めて鳴り、それが誤爆なら `git commit` がその日から恒久的に止まる。鳴っていないことは、動いている証拠ではない。

**誤爆を潰す。** 素の grep は、その禁止事項を説明しているコメント本文や、コミットメッセージそのものに当たる。コメント・クォート内・ヒアドキュメントを落としてから判定する。

**例外は握り潰さず、理由付きの定数に登録する。** 許可そのものが確認の記録になる — 「この FK は直前のマイグレーションが DROP している」。

**マネージャは lefthook を既定にする。** staged の glob 絞り込み(`glob:` + `{staged_files}`)と書き換え後の再 stage(`stage_fixed: true`)を1パッケージで賄える唯一の選択肢で、simple-git-hooks や husky はここで lint-staged を足すことになる。ただし述語がスクリプトにある以上、**乗り換えは `lefthook.yml` 数行の書き換えで済む** — ここは一方通行の扉ではない。

### 5. 残りを Claude Code のフックにする

雛形は [recipes.md](./recipes.md) にある。作法は5つ。

**拒否は終了コード 0 と `hookSpecificOutput.permissionDecision: "deny"` で返す。** 終了コード 2 でも今のところ止まるが、そちらは非推奨の経路である。

**判定できなかったら黙って通す。** `jq` が無い、JSON の形が違う — このとき拒否に倒すと、フックが壊れた瞬間に何も実行できなくなる。何も出力せず `exit 0` すれば通常の権限フローへ戻る。

**理由に逃げ道を書く。** `permissionDecisionReason` はモデルがそのまま読む唯一の文字列である。「禁止」だけ書くと迂回を探し始める。**代わりに何をすればよいか**まで書く — 「ゲートを飛ばさない。落ちた根本原因(型・lint・テスト)を直してから通す」。

**速く保つ。** マッチするツール呼び出しのたびに走る。フック自身がリポジトリ全体を走査すると、その分だけ毎回遅くなる。

**`Edit|Write` に掛けたフックは `Bash` を見ない。** パスで書ける保護は手順3で終わっているはずなので、ここの matcher が `Bash` になっていないなら、**3層目まで降ろす理由が無かった**合図である。

イベントの選び方:

| やりたいこと                     | イベント       | matcher                         |
| -------------------------------- | -------------- | ------------------------------- |
| 実行前に止める                   | `PreToolUse`   | ツール名(`Bash`、`Edit\|Write`) |
| 書いた直後に検査する             | `PostToolUse`  | ツール名                        |
| セッション開始時に環境を整える   | `SessionStart` | `startup\|resume\|clear`        |
| 応答を終える前に最後の関門を置く | `Stop`         | なし                            |

`SessionStart` の標準出力は**そのままコンテキストに入る**(`UserPromptSubmit` も同じ)。他のイベントの標準出力はデバッグログにしか出ない。

**`Stop` に重いゲートを置かない。** 応答のたびに走るので、型チェック1本(数秒)が上限である。テストや E2E は CI が持つ(`/kjfsm-skills:setup-ci`)。

### 6. 両方向を検査する

**弾く側だけ試して終えない。** 通す側が壊れている検査は、動いているように見えて作業を止める。

**弾く入力・通す入力・誤爆しそうな入力**の3種類を用意する。フックには JSON で流し込み(雛形は [recipes.md](./recipes.md) の 8)、検査スクリプトには実際のファイルをワーキングツリーへ作って走らせる。ユニットテストはそのうえで書く。

### 7. 置き場所と越えない線

- **`.claude/settings.json`** — コミットする。リポジトリを clone した全員とクラウドセッションに届く
- **`.claude/settings.local.json`** — 手元だけ。gitignore 済み。端末固有のパスを含むフックはこちら
- **`~/.claude/settings.json`** — 全プロジェクト。ここに置くものは「リポジトリ非依存」ではなく、**実行時にスコープを決める**もの。1本のフックの中でそのリポジトリを見て、該当しなければ黙って通す(`lefthook.yml` が無いリポジトリで `--no-verify` を止めても、飛ばす対象が無いので雑音でしかない)

⚠️ **フックはユーザーの権限で走る。** プロジェクトの `.claude/settings.json` のフックは、そのフォルダを信頼する前に走りうる。**リモートから取ってきたものを実行しない**、シークレットを読まない、書き込みをしない。

### 8. 散文側を追随させる

**層を移したら、その検査を名指ししている散文を全部辿る。** `CLAUDE.md`、`.claude/rules/`、`docs/agents/verification.md`、`docs/`、各スキル。

⚠️ **名前を置換するだけにしない。** 「フックが弾く」を「`permissions.deny` が弾く」に機械的に置き換えると、**旧フックの時代から嘘だった主張**がそのまま生き残る(`permissions.deny` はパスを名指ししない書き込みを見ないが、置換された散文はそこまで守られると書いていた)。書き直すのは名前ではなく、**その層で本当に何が止まるか**である。

機構にしたルールは、散文側では「何が弾くか」の1行に痩せさせる。同じことを両方に書くと、機構が黙って壊れた日に散文だけが残り、守られていると誤解したまま進む。

### 9. 完了

置いたものと、**それぞれが何を通すか**を層ごとにユーザーに伝える。散文側で痩せさせた行、**移した結果クローンと CI にも効くようになった検査**にも触れる。
