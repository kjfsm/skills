# テストを見直すパス

判定の軸は1つ: **どんな現実的な不具合を見逃すか** — 既にあるテストなら消したとき、テストの無い分岐なら今のスイートが。基準の本体は `test-auditor` が持つ。

**件数とカバレッジは、どちら向きにも目的にしない。** 1件も削れない・欠けが無いという結論は失敗ではない。

書く時点の規律は `tdd`、足場(設定・モックの構造)を作る・作り直すのは `workers-tests` の仕事である。ここは足場に手を付けず、書かれてしまった中身を見直して報告する。

## 手順1 — 全テストを列挙し、コストと規律を集める

作業用のディレクトリを1つ切り(`mktemp -d`)、以降の表はすべてそこに置く。**表をファイルに置くのは、この作業のコンテキストが途中で圧縮されても判定が残るようにするため**である。

- **列挙** — ユニット・統合・E2E のすべてのランナー(vitest の `projects` は1つずつ)について、設定の `include` / `testMatch` から対象ファイルを出し、`files.txt` に1行1パスで書く。ファイル名のパターンで grep するのは出発点にすぎない — ランナーが実際に拾う集合が正である。
- **所要時間と層** — 各ランナーを JSON レポーターで1回だけ回し、`パス<TAB>層<TAB>秒数` を `durations.tsv` に書く。層はランナー・プロジェクトの名前(`node` / `http` / `e2e` など)。回せないランナーは秒数の欄に「未計測」と理由を書いて進む — **推測で埋めない。**
- **skip** — ランナーの結果で skipped / pending だったテストを `skipped.tsv`(`ファイル:行<TAB>テスト名`)に書く。壊して確かめられないので、手順4ではなく報告の別枠に回る。
- **テストの規律** — 層の切り方やテストの書き方をリポジトリが決めている文書(`.claude/rules/` のテスト向けのもの、`AGENTS.md`、`docs/agents/` の該当節)のパスを `rules.txt` に書く。無ければ空のまま進む。
- **ゲートの在処** — `docs/agents/verification.md` があればそこに、無ければ `package.json` の scripts と CI の定義にある。

完了: `files.txt` がすべてのランナーの対象を漏れなく含み、各ランナーについて所要時間か「未計測」の理由があり、`rules.txt` が探した結果(空を含む)になっている。

## 手順2 — 対象ごとのスライスで棚卸しさせる

**`test-auditor` サブエージェントを、スライスごとに並列で起動する。** 判定の問い・分類・層の判定・欠けの基準・表の列・報告の形はそちらが1部だけ持つ — **ここには写さない。** 呼び出しのたびに貼り直す本文は、貼り忘れた日に黙って消える。

自分で読んで判定しない。数百ファイルを1つのコンテキストに入れると、後半ほど判定が雑になる。

- **切り方** — **同じプロダクションコードを対象にするテストを、層をまたいで1つのスライスに寄せる**(あるモジュールのユニットテストと、それを画面から確かめる E2E を同じスライスに)。ディレクトリや層で切ると、層をまたぐ重複と誤配置が別々のエージェントに割れて、誰にも見えなくなる。1体あたり30ファイル前後
- **渡すもの** — そのスライスのファイル一覧、書き出し先(`slice-<n>.tsv` と `gaps-<n>.tsv`)、`durations.tsv`・`rules.txt` のパス
- テストファイルが30本に満たなくても1体に渡す。毎回同じ経路を通すためである

完了: 全員の報告で「読んだ数 = 渡した数」であり、表に載ったファイルの集合が `files.txt` と一致する。

```bash
cut -f1 slice-*.tsv | sed 's/:[0-9]*$//' | sort -u | comm -3 - <(sort -u files.txt)
```

何か出たら、それが判定されていないファイルである。そのファイルだけで、もう1体に渡す。

## 手順3 — スライスをまたぐ対象を突き合わせる

突き合わせる対象は同梱のスクリプトが選ぶ。

```bash
bash ${CLAUDE_SKILL_DIR}/scripts/cross-slice.sh <作業ディレクトリ>
```

`all.tsv`・`gaps.tsv`(全スライスを束ねたもの)、`shared-targets.txt`、`groups.tsv`・`groups-gaps.tsv` ができ、対象の数が出る。0 なら、この手順は終わりである。そうでなければ `groups.tsv` と `groups-gaps.tsv` を **`test-auditor` 1体に突き合わせとして渡す**(書き出し先は `merged.tsv` と `merged-gaps.tsv`)。ここで自分が判定すると同じ基準が2か所に割れる。返ってきた行で `all.tsv` と `gaps.tsv` の該当行を置き換え、`groups-gaps.tsv` にあって `merged-gaps.tsv` に無い欠け(別のテストが既に守っていたもの)は `gaps.tsv` から消す。

完了: `shared-targets.txt` のすべての対象について、`all.tsv` と `gaps.tsv` の行が `merged.tsv` と `merged-gaps.tsv` の中身と一致している。

## 手順4 — `保留` を、壊して決める

`保留` の行には、決着をつける主張(「この条件を外すと、このテストが落ちるか」)が付いている。1件ずつ確かめる。

1. `git status` がクリーンであることを確かめてから始める
2. 主張どおりにプロダクションコードを1か所だけ壊す
3. 関係するテストファイルだけを走らせ、どれが落ちたかを見る。**ビルドを挟むランナー(E2E)は壊すたびにビルドし直し、前の回のサーバーを使い回させない**(`reuseExistingServer` が拾わないようポートを毎回変える、など) — 古いビルドに対して通ったテストは何も確かめていない
4. `git checkout -- <壊したファイル>` で戻す

**1件ずつ、順番に。** 並列にすると、どの破壊がどのテストを落としたのか分からなくなる。結果に従って、その行を `残す` / `削除` / `統合` に書き換える。`skipped.tsv` にあるテストの `保留` は確かめようがないので、書き換えずに報告の skip の枠へ回す。

完了: `保留` が0件か、残った `保留` のそれぞれに確かめられなかった理由がある。

## 手順5 — 報告して止まる

この順で応答に出す。

1. **削除・統合** — 省けるコストの大きい順。1件ごとに対象(`ファイル:行` とテスト名)と分類、**消すと見逃す不具合**(`無し`、または捕まえる別のテスト)、`統合` なら統合先と移すアサーション、省けるコスト(根拠があるものだけ)。末尾に件数と、ファイルごと消える分の合計秒数 — **一部だけ消すファイルの短縮分は測っていないので、足さない**
2. **壊して確かめた結果** — 壊した箇所、落ちたテスト、それで決まった判定
3. **層の誤配置と規律違反** — 列 9 が `-` でない行。`ファイル:行`・今の層→移す層・根拠にした規律の箇所
4. **欠け** — `gaps.tsv` を重要度で束ねる。対象・どこにもテストの無い分岐や規則・見逃している不具合・置くべき層
5. **放置された skip** — `skipped.tsv` の全件と、それぞれが何を守るはずだったか
6. **所要時間の上位にあるのに `残す` と判定したもの** — 見逃す不具合を1行ずつ。監査が遅さの原因を挙げていればそれも添える。削らない判断も判断であり、ユーザーはコストの大きいものほどその根拠を見たい
7. **判断がほしい** — 監査の判定に異を唱えるもの。判定を自分で書き換えず、ここに分けて両方の言い分を並べる

**ここで止まる。消さない、移さない、足さない。** どれを当てるかはユーザーが1件ずつ決める。

## 承認されたものを当てる

`統合` と層の移動は、先に行き先へアサーションを移してから元を消す。欠けを埋めるテストは `tdd` の規律で書く — そのテストは、欠けとして挙げた不具合を入れたときに落ちなければならない。終えたら `verification-loop` スキルでクリーンランを取る。

コミットメッセージには、消したものごとの「見逃す不具合: 無し / 捕まえる別のテスト」を書く — 消えたテストについての Why は、コミットログにしか残らない。
