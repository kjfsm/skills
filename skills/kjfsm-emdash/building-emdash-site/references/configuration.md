# 設定

> 設定項目の一覧・意味は公式を読むこと。
> [reference/configuration](https://docs.emdashcms.com/reference/configuration/)(`emdash()`の全オプション、`live.config.ts`)、
> [deployment/cloudflare](https://docs.emdashcms.com/deployment/cloudflare/)(`wrangler.jsonc`、D1/R2/KV、read replica、Workers Cache)。
> ここに書くのは、公式に載っていないこのサイト群固有の方針と、型生成まわりの実際の挙動だけ。

## デプロイ先はCloudflareに固定する

これらのサイトはCloudflare(D1 + R2 + KVキャッシュ)にデプロイする。`emdash()`には
`database: d1(...)`・`storage: r2(...)`・`objectCache: kvCache(...)`を渡す。設定例は公式の
[deployment/cloudflare](https://docs.emdashcms.com/deployment/cloudflare/)にそのまま載っている。

EmDashはNode.js(`@astrojs/node` + `sqlite`/`local`ストレージ)やリバースプロキシ配下のセルフホストにも
対応するが、これらのサイトでは採用しない。他アダプタの構成が必要になったときだけ
[deployment/nodejs](https://docs.emdashcms.com/deployment/nodejs/)を読む。

## 型生成: `emdash-env.d.ts` と `.emdash/types.ts` は別物

公式は`emdash types`が生成する`.emdash/types.ts`しか説明していないが、実際にはEmDashインテグレーションが
**devサーバー起動時に**プロジェクトルートへ`emdash-env.d.ts`を自動生成する(ファイル冒頭に
`// Generated by EmDash on dev server start`が入る)。`tsconfig.json`がincludeしているのはこちらで、
スキーマが変わると自動で再生成される。

つまり:

- **型を更新したい** → devサーバーを起動し直すのが手軽(`emdash types`ではない)
- `npx emdash types`の既定の出力先は`.emdash/types.ts`で、`emdash-env.d.ts`は**更新されない**

生成される型には、コレクション固有のフィールドに加えて、事前ロードされる`bylines`(著者クレジットの配列)と
`terms`(タクソノミー名 → 用語配列のレコード)が含まれる。

```typescript
// Generated by EmDash on dev server start
/// <reference types="emdash/locals" />

import type { ContentBylineCredit, TaxonomyTerm, PortableTextBlock } from "emdash";

export interface Blog {
  id: string;
  slug: string | null;
  status: string;
  title: string;
  featured_image?: { id: string; src?: string; alt?: string; width?: number; height?: number };
  content?: PortableTextBlock[];
  createdAt: Date;
  updatedAt: Date;
  publishedAt: Date | null;
  bylines?: ContentBylineCredit[];
  terms?: Record<string, TaxonomyTerm[]>;
}

declare module "emdash" {
  interface EmDashCollections {
    blog: Blog;
  }
}
```

画像フィールドが`src`であって`url`ではない点に注意(公式のField Types Referenceは`url`と書いているが誤り)。
