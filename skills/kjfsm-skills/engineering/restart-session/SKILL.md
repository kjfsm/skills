# セッションを再起動する

`claude respawn <id>` はプロセスだけを立て直し、ID・会話・worktree はそのまま残す。プラグインや設定は起動時に読まれるので、これで読み込み直される。

対象が自分自身なら、1. 以降は走らせず「[自分を再起動する](#自分を再起動する)」へ進む。

## 1. 対象を引く

```bash
claude agents --json | jq '.[] | {id, name, cwd, kind, state}'
```

名前か ID で対象の行を選ぶ。`kind` が `background` でなければ `respawn` は効かない — 端末で直接動いているセッションなので、そちらで `/exit` してから `claude --resume <session-id>` で開き直すよう伝えて終える。

**対象が自分なら止まる。** 自分の ID は `${CLAUDE_CODE_SESSION_ID:0:8}` である。自分を `respawn` すると、立て直しを見届ける者がいなくなる — 「自分を再起動する」へ移る。

完了基準: 対象の ID が1つに決まり、`background` であり、自分ではないと確かめた。

## 2. 失われるものを見る

`state` が `working` なら、相手は作業の途中である。`blocked` なら答えを待っているプロンプトがある。どちらかなら画面を読む:

```bash
claude logs <id> | sed 's/\x1b\[[0-9;?]*[A-Za-z]//g' | tail -40
```

再起動で残るのは会話と worktree のファイルだけである。走っているシェル、待機中のタスク、答えを待っているプロンプトは失われる。そのどれかがあれば、該当の1〜3行を引いてユーザーに伝え、続けてよいか確かめる。`done` で入力待ちなだけなら確かめずに進む。

`run_in_background` で立てた開発サーバーは、プロセスを立て直しても別のプロセスグループで生き残り、ポートを握ったまま誰も覚えていない孤児になる。止めるべきものがあるなら、再起動ではなく相手に `/kjfsm-skills:close-session` を走らせる方が先である。

完了基準: 失われるものが無いか、それをユーザーに伝えて続行の返事を得た。

## 3. 立て直す

```bash
claude respawn <id>
```

10 秒ほどおいて 1. のコマンドで同じ ID の `state` を見る。`blocked` なら 2. と同じく画面を読み、何で止まっているかを引く。

## 4. 返ってきたものを伝える

状態をそのままユーザーに伝える。**止まっているなら、代わりに答えない** — 何で止まっているかと `claude attach <id>` の行を渡し、人間に任せる。

完了基準: 対象を同じ ID で立て直し、「動いている」か「何で止まっている」かをユーザーに伝え、`claude attach <id>` の行を渡した。

## 自分を再起動する

自分では見届けられないので、同じマシンの別のセッションに上の 1.〜4. を走らせてもらう。

1. **バックグラウンドセッションか確かめる。** `claude agents --json` で自分の ID の行の `kind` が `background` でなければ — `/exit` してから `claude --resume $CLAUDE_CODE_SESSION_ID` で開き直せると伝えて終える。
2. **自分が立てたものを止める。** 走っているバックグラウンドのタスクと答えを待っている確認があればユーザーに伝え、続けてよいか確かめる。開発サーバーは `/kjfsm-skills:close-session` の「2. 自分が立てたものを止める」で止める — 立て直した自分はそれを覚えていない。
3. **頼む相手を選ぶ。** `ListAgents` から、このマシンで `idle` の対話セッションを1つ選ぶ。自分を立てたセッションが居ればそれを選ぶ。リモートやクラウドのセッションは選ばない — このマシンの `claude respawn` に手が届かない。
4. **返答の最後の操作として頼む。** `SendMessage` の1行目で「`/kjfsm-skills:restart-session` で `<自分の ID>` を再起動してほしい」と言う。相手が 2. で状態を読むとき、こちらは入力待ちに戻っていなければならない — 頼んでから作業を続けると、`working` のまま止められる。

ユーザーには、誰に頼んだかと `claude attach <自分の ID>` の行を先に伝えておく。送った相手から受け取りを断る `[Cross-session delivery notice]` が返ったら、別の相手に頼み直すか、ユーザーに `claude agents` で自分を選んで手で `respawn` できると伝える。

完了基準: 止めるべきものを止め、頼んだ相手と `claude attach` の行をユーザーに伝えてから、返答の最後に依頼を送った。
