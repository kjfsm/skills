# `/init` の出力を出発点にせず、メモリファイルは「発見不可能 ∧ グローバルに有用」で絞る

`tend-memory-files` の手順2 は長らく「`/init` を実行する」から始まっていた — Claude にコードベースを解析させ、ビルドコマンド・テスト手順・規約の下書きを作らせ、そこから削る、という順序である。この出発点を捨てる。

## 実測が言っていること

[Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?](https://arxiv.org/abs/2602.11988)(Gloaguen, Mündler, Müller, Raychev, Vechev / 2026-02、v2 2026-06)は、複数の LLM とコーディングエージェントにまたがって、リポジトリレベルのコンテキストファイルが **タスク成功率を平均で上げず、推論コストを 20% 以上増やす** ことを示した。

ただし論文の結論はもう一段細かい: **「リポジトリの概要は役に立たないが、明示的な指示は従われる」**。否定されたのは _概要_ であって _指示_ ではない。この切り分けがこの ADR の土台である。`/init` が生成するのはほぼ全部が前者だからこそ捨てられる。

Anthropic 公式も同じ側に立っている。[The new rules of context engineering for Claude 5 generation models](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models)(Thariq Shihipar / 2026-07-24)は Claude Code のシステムプロンプトを 80% 以上削ってコーディング eval に劣化が出なかったと報告し、`CLAUDE.md` については「リポジトリが何のためのものかを短く書き、トークンの大半は **gotcha** に使え。ファイルシステムやリポジトリを見れば Claude に分かることを書くな」としている。

## 決定

1. **`/init` の出力を下書きにしない。** 走らせてしまった後は、生成された各行を採用基準にかける。ほとんど残らないのが正常である。
2. **採用基準は二条件** — **発見不可能**(コード・config・型・検査スクリプトが答えを持っていない)かつ **グローバルに有用**(どのパスを触っていても要る)。片方でも欠けたら宛先が違う: 発見できるものは書かない、グローバルでないものは `.claude/rules/` かスキルへ。
3. **行数の目安より二条件が先。** 200行(公式ドキュメントの目安)は上限であって合格点ではない。二条件を通った行だけを残した結果が200行を大きく下回るのが普通である。
4. **決定的に弾けるものは散文で頼まない。** 検査スクリプト・lint・型が捕まえるルールを `CLAUDE.md` に書くと、コンテキストを払ったうえに「守られたか」を読む側が確認できない。散文が持つのは、機械が弾いた後に残る判断だけである。

この決定に従うのは `tend-memory-files`(手順1・2・6、および隣接するコンテキストの大きい方を先に見る手順9)、`setup-rules`(手順4)、そしてこのリポジトリ自身の `CLAUDE.md` である。

## 却下: 「`CLAUDE.md` をほぼ空にする」

[Never Run Claude /init](https://www.aihero.dev/never-run-claude-init)(Matt Pocock)は同じ論拠から、`CLAUDE.md` 全文を `you are on WSL on Windows` の6語まで削ることを勧めている。採らない。

- 論文が否定したのは概要であって指示ではない。**腐るのは記述**(ファイルパス、サービス関係、アーキテクチャ図)で、**腐らないのは不変条件と外部制約**(「`version` を両方から省くとコミット SHA がバージョンになる」)である。この2つを一緒に捨てる理由が無い
- 6語で足りるのは単独の端末で自分だけが作業する場合である。複数のエージェント・サブエージェント・`~` を持ち越せないクラウドセッションが同じ不変条件を破りうるリポジトリでは、探索フェーズは「破ってはいけない」を教えてくれない — 探索が読むのは現状であって禁止事項ではない
- 探索フェーズを信じる、は **見れば分かること** にしか使えない。見ても分からないことは、常駐しているか、存在しないかのどちらかである

## 指示の個数を根拠にしない

「LLM が守れる指示は N 個」という instruction budget の概念は使うが、**数値は根拠にしない**。出典が割れている: [Kyle / HumanLayer](https://www.humanlayer.dev/blog/writing-a-good-claude-md) は 150〜200 個(Claude Code のシステムプロンプト自体が約50個を使う)、Matt Pocock は 300〜400 個(大きいモデルで500)。どちらも実測ではない。「長いほど従われなくなる」は使えるが、「N 行までなら安全」は言えない。

## 保留: 常駐しているコメント規約と、ハーネスの「周囲に合わせろ」

[c5] は、Anthropic 自身が社内のトランスクリプトで見つけた失敗として、1リクエストの中でシステムプロンプト・スキル・ユーザー依頼が衝突する例を挙げている — 「適宜ドキュメントを残せ」と「コメントを追加するな」が同時に来ると、Claude はどれに従うかを先に考えることになる。旧システムプロンプトの「コメントは既定で書くな」は、いまは **「周囲のコードと同じように書け — コメント密度・命名・イディオムを合わせろ」** に置き換わっている。

このリポジトリが3か所に常駐させているコメント規約(`output-styles/kjfsm.md`、`CLAUDE.md`、`setup-skills` の `### Conventions`。検査 16. が3か所を見る)は **「コードを読めば分かることは書かない」** で、**コメントの多いコードベースでは向きが逆になる**。

**いまは変えない。** このリポジトリの規約自体が「ルールが増えるのは同じ指摘を2回受けたとき」であり、衝突を実際に踏んだ観測がまだ無い。先回りで一句足すと、衝突を1つ減らすつもりで衝突をもう1つ作る側に回りうる。

踏んだときに足すのは、常駐ブロックへの1句(「周囲が冗長でも合わせない」に相当するもの)で、3か所同期と検査 16. の対象になる。判断材料として先に確かめるべきなのは、**衝突しているのか、順序が決まっているだけなのか** — 「読めば分かることは書かない」は宛先のルーティングであって禁止ではないので、「周囲に合わせろ」の下位規則として読める余地がある。踏んだ実例が出るまでは、どちらなのかを決められない。
