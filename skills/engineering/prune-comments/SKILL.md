# コメントを削るパス

**書く瞬間に自制させるのではなく、書かれたものを別のパスで削る。** 規約をいくら常駐させても、コメントの饒舌さは指示を上書きする強さで出てくる([anthropics/claude-code#65961](https://github.com/anthropics/claude-code/issues/65961) — CLAUDE.md・メモリ・フックを積み上げても部分的にしか効かない)。予防の層には天井があるので、回収はここで行う。

## 手順0 — 増えていなければ降りる

このパスは `/implement` のコミット前の並びに**必ず**入る。だから最初に機械的に数え、**コメント行が1行も増えていなければ、何もせず終える** — サブエージェントは立てない。必須の並びに置きながらコストを条件付きに保つための段であって、ここでは何も判断しない。

```bash
exts=(-- '*.ts' '*.tsx' '*.js' '*.jsx' '*.go' '*.rs' '*.java' '*.c' '*.h' '*.cpp' '*.cs' '*.swift' '*.kt' '*.php' '*.dart' '*.vue' '*.svelte' '*.css' '*.scss' '*.py' '*.rb' '*.sh' '*.sql')
{ git diff "$(git merge-base <基点> HEAD)" "${exts[@]}"
  git ls-files --others --exclude-standard "${exts[@]}" | while read -r f; do git diff --no-index /dev/null "$f"; done
} | grep -cE '^\+[[:space:]]*(//|/\*|\*[^/]|#($|[^!])|--[^-])'
```

範囲は基点とのマージベースから **作業ツリー** まで — `/implement` はコミットの前にこのパスを通すので、`<基点>...HEAD` では書いたばかりのコメントが1行も数えられない。未追跡の新規ファイルは `git diff` に出ないので、2行目で `/dev/null` との差分として足している。

拡張子を絞るのは、`#` が Markdown では見出し、YAML ではキーだからである。**この正規表現は全言語のコメント記法を一括で当てるので多めに数える**(シェルの `case` の `*)` が C 系の枝に当たるなど)— 判定は「0 か、0 でないか」だけなので、多めに出て困るのは無駄に1回走ることだけであり、拡張子ごとに振り分ける複雑さに見合わない。0 が返ったら、その旨だけ伝えて終える。

## 走らせ方

**`comment-pruner` サブエージェント1体に渡す。** このプラグインが配っており、6段のルール・残す基準・報告の形はそちらが1部だけ持つ — **ここには写さない。** 呼び出しのたびに貼り直す本文は、貼り忘れた日に黙って消える。

自分で読みながら消さない。**直前に自分で書いたコメントは、目的が思い出せてしまう分だけ残す方向に倒れる。** 汚れていないコンテキストであることが、このパスの効きの半分を占める。

渡すのは、この実行でしか決まらないものだけである:

- **範囲** — 差分の中で触れたファイルと未追跡の新規ファイルのコメントだけ。基点はユーザーが言ったもの、無ければ `git fetch` で最新にした `origin/<既定ブランチ>`。差分は手順0と同じく、マージベースから作業ツリーまで
- 継承した古いコメントまで広げてよいのは、**ユーザーが明示的にそう求めたとき**だけ

## 返ってきたものを読む

**減った行数で評価しない。** 減らすことを目標にすると、全消しが最適解になる。**1行も消さなかったという報告は失敗ではない。**

報告に載っている「判断が割れたもの」だけ、消した理由を読んで妥当性を見る。戻すなら `git checkout` である。

## このパスがやらないこと

**足さない。** 書かれるべきだったのに書かれていない Why not を探すのは、差分に写っていないものを探す作業で、消す作業とは要求される見方が逆である。同じパスに混ぜると、削る手が緩む。そちらは `/two-axis-review` の Standards 軸が受け持つ。
