# ブラウザゲームを作る

参考実装は `~/github/kjfsm/game-01`(もちずもう — 土俵で押し出し合う対戦。本番は `https://mochi-sumo.kjfsm.net`)。形に迷ったらそこを開く。このスキルが持つのは **順序と、その実装で踏んだ手戻り** である。

通信まわり(DO と画面)で踏んだものは [NETCODE.md](NETCODE.md)、本番に出す順は [DEPLOY.md](DEPLOY.md)。

## 1. 何を作るか決める

面白さは作ったあとからは足しにくい。次の4つを満たす案を選ぶ:

- 縦持ちのスマホで、片手の親指で動き、もう片手で1つのボタン
- 1回の勝負が 20〜40 秒。負けてもすぐ次が始まる
- ひとりでも遊べる(人が足りなければ CPU が埋める)。友だちとは合言葉の部屋で
- 決着の瞬間に名前が付く(もちずもうなら決まり手)。演出と実況の種になる

完了基準: 遊び方を1文で言えて、4つとも満たす。

## 2. 土台を起こす

`cf-workers-full-stack-template` から起こす(kjfsm-auth の RP と共有 D1 の相乗りが組み込み済み)。手順はテンプレートの README「フォークしたら」が持つ。そこに無い落とし穴:

- 手元の clone は古いことがある。`git fetch` してから `git archive origin/main | tar -x -C <新しいリポジトリ>` で写す
- テンプレートの `kjfsm/cf-workers-full-stack-template#11` より前の版から起こした場合は、次の2つを踏む
  - README の置き換え手順が `git grep` になっている。写した直後はファイルが未追跡なので、何も拾わない。`grep -r --exclude-dir=node_modules` を使う
  - origin/main に `wrangler.jsonc` がまだ無く、`check:migrations` が `git show` で落ちる。#11 の `existsAt` の形で直す
- 手元のポートは `grep -rhoE 'port: ?[0-9]{4}' ~/github/kjfsm/*/vite.config.ts` で空きを探す

完了基準: 名前・slug・ポートを置き換え、テンプレートの検証ゲートが緑のままコミットした。

## 3. 勝負の計算を純粋な TS に置く

勝負は DO にも画面にも依らないクラス(game-01 の `app/game/match.ts`)に入れる。乱数は種つきのものを外から渡し、時刻は tick の数から作る。node 層のテストで、勝負を種から再現する。

動きの式(加速・衝突・突進)は `physics.ts` の1か所に置き、サーバーと手元の予測が同じ関数を呼ぶ。2か所に書くと両者がずれ、手元の補正がいつまでも止まらない。

**決着は「残りが1つになった瞬間」に決める。** 落ちきるのを待ってから残りを数えると、困ることが2つ起きる。押し出した勢いで自分も落ちた側が引き分けになり、先に落ちた側に手柄がつく。手柄は、そのときまだ場に残っている相手にだけつける。

完了基準: 勝ち・引き分け・手柄・途中で抜けた人の扱いを、種つきのテストで1本ずつ確かめた。

## 4. 数をシミュレーションで決める

CPU 同士の勝負を数百回回すスクリプトを最初に置く(game-01 の `pnpm sim`)。**勝負の長さと一緒に、最初の脱落までの時間を測る。** もちずもうの最初の値では、勝負の長さは平均 16 秒でまずまずに見えた。ところが最初の押し出しは平均 3.8 秒で来ていて、早い回は 2 秒を切っていた。人間が自分のキャラを見つける前に終わる。これを2つの手で直した。

- 反発・突進の重さを下げ、抵抗を上げる
- 出だしの 1.5〜3 秒は CPU に様子見させる

人間が全員抜けたら CPU 同士を早回しする、といった仕組みはシミュレーションでは切る。コンストラクタで倍率を渡す形にすれば、共有の定数を書き換えずに済む。

完了基準: 勝負の長さと最初の脱落までの時間の分布を出した。数を変えたら回すことを、そのリポジトリの `.claude/rules/` に書いた。

## 5. 部屋を Durable Object にする

部屋1つを DO 1つにし、人がいる間だけ固定の tick で勝負を進めて全員へ配る。手元からは、入力が変わったときだけ送る。守ることは [NETCODE.md](NETCODE.md) の「サーバー」。

完了基準: bindings 層のテストで DO に WebSocket を張り、次の3つを確かめた。

- welcome・顔ぶれ・状態が届く
- 満員なら断られる
- 同じアカウントで入り直すと、古い接続が閉じる

## 6. 画面を作る

盤面は canvas に描き、HUD だけを React に載せる。自分のキャラは手元で先に動かし、他人は補間して描く。守ることは [NETCODE.md](NETCODE.md) の「画面」。

スマホの操作は2つに分ける。画面の左半分は、触れた位置を中心にしたスティックにする。右半分は、どこを叩いてもボタンにする。ほかに `touch-action: none` と safe-area を入れ、縦持ち・横持ちの両方で配置を決める。

完了基準: 次の観測で、縦・横・PC の3台が同じ部屋で遊べる。

## 7. ログインと名前をつける

ログインそのものは `/kjfsm-personal:connect-kjfsm-auth` に従う。名前まわりは、game-01 で公開したあとにユーザーから直された。そのときの形は [ACCOUNT.md](ACCOUNT.md) にある。直されたのは次の3つ。

- IdP の名前が番付に出る
- 「kjfsm でログイン」では何でログインするのか分からない
- 名前をあとから変えたい

完了基準: 次の2つを満たした。

- 初回のログインで名前を聞かれる。設定画面で変えると、トップにも番付にも新しい名前が出る
- 名前の無いアカウントを全ページで `/welcome` へ送り、`/api/auth` だけは通すことを、テストで撃った

## 8. 観測する

Playwright をスクリプトで回し、iPhone の縦・横と PC の3台を同じ合言葉の部屋に入れる。タッチは CDP の `Input.dispatchTouchEvent` で入れる。スクリーンショットで次を見る:

- 右上の人数が、入れた人の数と合う(合わなければ幽霊 → [NETCODE.md](NETCODE.md))
- HUD が盤面やボタンに重ならない。iPhone SE の縦持ちと、横持ちの低い画面でも見る
- 勝負の開始・脱落・決着・次の勝負までが一巡する
- ログインしたまま1勝負を終えると、番付が積まれる

描画の途中にスクリーンショットが入ると、ハイドレーションの差分(`caret-color`)が出ることがある。Playwright がカーソルを隠すために入れるスタイルなので無視してよい。

完了基準: 上の4つをスクリーンショットで見て、見つけた崩れを直した。

## 9. 二軸レビューを回す

`/kjfsm-skills:two-axis-review` を、テンプレートから起こしたコミットを基点に回す。スペックはユーザーの依頼文そのもの。もちずもうで Spec 軸が拾ったものは、作る段階で先に潰しておく:

- IdP のプロフィール名がしこ名の既定になり、番付に本名が出る(→ 手順 7)
- 同点の順位が、一覧(並び順の通し番号)と自分の欄(点の高い人の数 + 1)で食い違う
- 同じアカウントを2つ並べて、自分で自分を押し出して点を積める
- 勝負の途中で抜ければ、負けが記録されない
- 友だちの部屋にも CPU が必ず入り、1対1ができない

完了基準: 両軸の指摘を直したか、直さない理由を持った。

## 10. 本番に出す

[DEPLOY.md](DEPLOY.md) の順で進める。どの手順も本番に触るので、始める前にユーザーの確認を一度にまとめて取る。何をどの順で触るかを列挙し、作るテーブルの数まで正しく書く。

完了基準: 本番の URL で2台が同じ部屋に入れて、IdP の認可エンドポイントがクライアントを受け付けた。実機での確認・IdP を通したログインの一巡・PR のマージは人間に渡した。

## 直すときの注意

整形(oxfmt)のあとに、文字列置換のスクリプトで直さない。折り返しで一致しなくなり、置換が黙って空振りする。もちずもうでは、Wake Lock を取る行がこれで抜けたまま、レビューまで気づかなかった。直すときは Edit を使うか、置換した件数を assert する。
