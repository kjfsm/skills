# セッションを再起動する

閉じる側はここで済ませ、立てる側は `session-launcher` サブエージェントに渡す — 名前と `--resume` の ID があれば、立て直しは新規に立てるのと同じ手順である。

## 1. 対象を引く

対象は tmux のセッション名 `<リポジトリ>_worktree-<名前>` で受け取る。最初の `_worktree-` で割って、リポジトリと worktree 名を得る。

```bash
tmux display-message -p -t "$TMUX_PANE" '#S'                  # 自分のセッション
tmux display-message -p -t <セッション名> '#{pane_current_path}' # 対象の worktree パス
```

**対象が自分のセッションなら止まる。** 閉じた時点でこの手順ごと消え、立て直す者がいなくなる。

完了基準: worktree 名と worktree パスが揃い、対象が自分ではないと確かめた。

## 2. 失われるものを見る

```bash
tmux capture-pane -p -t <セッション名>
```

再起動で残るのは会話と worktree のファイルだけである。走っているシェル、待機中のタスク、答えを待っているプロンプトは失われる。画面にそのどれかがあれば、該当の1〜3行を引いてユーザーに伝え、続けてよいか確かめる。入力欄が出ているだけなら確かめずに進む。

`run_in_background` で立てた開発サーバーは、kill しても別のプロセスグループで生き残り、ポートを握ったまま誰も覚えていない孤児になる。止めるべきものがあるなら、再起動ではなく相手に `/kjfsm-skills:close-session` を走らせる方が先である。

完了基準: 失われるものが無いか、それをユーザーに伝えて続行の返事を得た。

## 3. session-id を得る

```bash
dir=~/.claude/projects/$(printf %s "<worktree パス>" | tr '/.' '--')
ls -t "$dir"/*.jsonl | head -1
```

ファイル名から `.jsonl` を除いたものが session-id である。`subagents/` 配下のログは子のもので、上のグロブには掛からない。

**閉じる前に引く。** 閉じたあとで見つからなければ、戻す会話が無いまま壊しただけになる。

完了基準: session-id が1つ得られた。

## 4. 閉じる

```bash
tmux kill-session -t <セッション名>
```

## 5. 立て直させる

`session-launcher` に、1. の worktree 名と 3. の session-id だけを渡す。手順と報告の形はエージェントが持つので、ここに書き足さない。

**名前は変えない。** `claude -w` は名前で worktree を引くので、別の名前を渡すと新しい worktree が生え、会話だけが空の作業ツリーに移る。同じ理由で、立て直しで信頼ダイアログが出たら名前を取り違えている — 信頼ダイアログが出るのは初めて開くディレクトリだけである。

## 6. 返ってきたものを伝える

状態をそのままユーザーに伝える。**止まっているなら、代わりに答えない** — 何で止まっているかと `tmux attach` の行を渡し、人間に任せる。

完了基準: 対象を閉じて同じ worktree と session-id で立て直し、「入力欄が出ている」か「何で止まっている」かをユーザーに伝え、`tmux attach` の行を渡した。
