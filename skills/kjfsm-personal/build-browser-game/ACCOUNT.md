# ログイン・名前・番付

game-01(もちずもう)で、公開したあとにユーザーから直された形と、全体レビューで拾ったもの。ログインそのもの(RP の組み方・ボタンの文言)は `/kjfsm-personal:connect-kjfsm-auth` を見る。

## 名前の置き場所

- **ログインした人の名前は、アプリ側のテーブル(`<slug>_profile`)にアカウントごと1つ持つ。** IdP の `user.name` は使わない
- **ゲストの名前は端末(localStorage)に持つ。** サーバーで描かれる部品では `useSyncExternalStore` で読む(→ NETCODE.md)
- **名前の入力欄は `autoComplete="off"` にする。** `name="name"` の欄には、ブラウザが氏名(本名)の自動入力を差し出す

## 初回のログインで聞く

関所は root の middleware の1か所に置く。middleware は、アカウントを要求ごとに1回だけ引いて context に置く。名前の無いアカウントは、どのページを開いても `/welcome?redirectTo=<元のパス>` へ送る。

- **`/welcome`・`/login`・`/api/*` は通す。** `/api/` まで止めると、ログアウトもできなくなる
- **パスは `.data` を落としてから見る。** 画面の中の遷移と送信はデータ要求で届く(→ `/kjfsm-skills:react-router-route-module`)。落とさないと、名前を決める送信そのものを関所が `/welcome` へ送り返し、名前を決められない
- **loader ごとに判定を書かない。** 写し忘れたページ(game-01 では番付)が、ビルドもテストも通ったまま素通りになる。`/login` も含め、どのページもセッションを自分で引き直さず、context から読む
- **アカウントを引けなかったら、ゲストとして通す。** middleware が投げると、全ページが 500 になる。game-01 では、テーブルより先にコードが出て、ログインした人の全ページが落ちた
- **ログインの戻り先(`callbackURL`)は元のページのままでよい。** 戻った直後の要求を middleware が捕まえる
- **`/welcome` は、ページ自身の middleware でログインを要求する。** loader と action に同じ判定を2回書かない
- **土俵の WebSocket は React Router の外にあり、関所を通らない。** 名前の無いアカウントはゲストとして扱い、userId を DO へ渡さない。渡すと、端末の名前のまま番付に積まれる

### テスト

- **名前の無いアカウントで、全ページぶん「送られる」を撃つ。** あわせて、`/api/auth` と `/login` が通ることも撃つ
- **開発用の入口の種の人を、役ごとに分ける。** 名前を決めないまま使う人と、決める人を分ける。http 層は D1 をファイルの中で共有するので、分けないとテストの順序に乗る
- **E2E は、種の人の名前を毎回まっさらに戻してから始める。** 開発用の入口で戻せるようにする。戻さないと1回目しか通らず、手元の2回目も CI のリトライも落ちる

## 変えられるようにする

- **設定画面(`/settings`)で変えられるようにする。** ゲストは同じ画面で、端末の名前を変える
- **土俵(DO)へは、アカウントの名前を Worker からヘッダで渡す。** 手元から送られた名前は、ゲストのときだけ使う。日本語はヘッダにそのまま載らないので、`encodeURIComponent` して載せる

## 番付

- **名前は `coalesce(profile.name, stats.name)` で読む。** 取組の結果は、土俵が入室時に持った名前で書かれる。そのため stats の名前だけを見ていると、名前を変える前から開いていたタブの取組が終わった時点で、番付が古い名前に戻る。stats の名前に落とすのは、profile を持たない行(profile のテーブルより前に書かれた成績)があるためである
- **同点は同じ順位にする。** 一覧を並び順の通し番号にして、自分の欄を「自分より点の高い人の数 + 1」にすると、同点の人の順位が食い違う。どちらも後者に揃える
