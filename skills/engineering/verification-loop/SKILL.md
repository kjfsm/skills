# 検証ループ

変更が動くと確かめるとは、記録された **ゲート** を順に通し、最後に **クリーンラン** — 中断も編集も挟まない1回の通し実行 — を取ることである。途中で見た緑は数えない。

## ゲートを揃える

**ゲート** とは、合否が二値で出る1つのコマンドである。

`docs/agents/verification.md` が、このリポジトリのゲートとその順序の情報源である。存在すれば、記録された順にそのまま走らせる。

存在しなければ、リポジトリが実際に使っているコマンドを見つけ出す — `package.json` の scripts、`Makefile` や `Taskfile`、`.github/workflows/` などの CI 設定。**CI が回しているものが、そのリポジトリが本当に守っている契約である。**

## 赤を直す

- **一目で原因のわからない赤は `/diagnosing-bugs` に引き渡す。** あちらは信号が無いところに信号を作るスキルであり、ここはすでにある信号を回すスキルである。
- **変更前から赤だったゲートは、そう述べてから先へ進む。** 切り分けは同梱の [scripts/baseline-diff.sh](scripts/baseline-diff.sh) が行う — `bash ${CLAUDE_SKILL_DIR}/scripts/baseline-diff.sh [--base <ref>] [--extract <regex>] -- <ゲートのコマンド>` を実行する。返ってきた `NEW` が直す対象のすべてで、`PRE` はそのまま報告する。終了コード `2` は「比較できなかった」であり、緑ではない。

- **カスタムチェックを適用する。** `docs/agents/verification.md` の **カスタムチェック** のうち、この差分が触れているものを実行し、違反を `file:line` で挙げてから直す。ここに属するのは決定的に実行できるもの — コマンド、grep、テスト — だけである。判断が要るものは `/two-axis-review` が読む。
- **ゲートは動かさない。** 緑は、コードがゲートを満たしたときにだけ手に入る。ゲートそのものを変える必要が本当にあるなら、それは検証ではなく **変更の一部** として、理由とともに提示する。

## 観測する

すべてのゲートが緑でも、それは「壊れていない」であって「動く」ではない。ビルドして起動し、**変更した経路を自分で1度駆動する**。

取得した **証拠** をそのまま貼る — HTTP ならレスポンス本文、CLI なら stdout、UI ならヘッドレスブラウザで撮ったスクリーンショットか DOM。

観測は記録されたゲートの **最後の1つ** である — つまりクリーンランの中に含まれる。ここで先に一度駆動しておくのは、通しで何を駆動すればよいかを決めるためである。

**完了基準:** 変更した振る舞いを実際に駆動した実行があり、その出力を貼っている。テストが緑であることは観測の代わりにならない。駆動できるものが何もないとき(公開インターフェースを持たない純粋なライブラリなど)は、そう述べる。

## クリーンランを取る

最後の編集を終えたあと、ゲートを最初から最後まで一度に通す — 観測もその通しの中で取り直す。編集を1つでも挟んだランは無効である。

直しているうちに別のゲートを壊しているのが普通である。

**完了基準:**

- [ ] 中断のない1回の通し実行で、観測を含む記録されたすべてのゲートが緑になった
- [ ] **その通しの中で** 取れた出力と証拠を貼った — 最後の編集より前に取った証拠は数えない

## ラチェットを1段上げる

この実行の中で **手作業で見つけて直したもの** を思い出す。そのうち実行できるチェックにできるものを、`docs/agents/verification.md` のカスタムチェックに書き足す。

ラチェットには段がある。上へ行くほど仕込みが要り、その代わりに見張りが要らなくなる:

1. **手作業** — 毎回あなたが気づく。
2. **カスタムチェック** — このスキルが回すので、このスキルを通ったときに捕まる。
3. **フック** — ハーネスが実行するので、誰が何を呼ぼうと捕まる(編集の後、コミットの前、ターンを終える前)。

毎回、例外なく成り立っていなければならないチェックは3段目に置く — そこはこのスキルの外である。

**完了基準:** 今回手で捕まえた不具合は、次回はゲートが捕まえる。手で見つけたものがなければ、何も書かない。
