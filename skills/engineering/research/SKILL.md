# リサーチ

**調査対象の問い: $ARGUMENTS**

これはフォークされたコンテキストで走る。呼び出した側の会話は見えないので、**判断の材料はこの本文と上の問いだけ** である。問いが空、あるいはそれだけでは何を調べるべきか決まらないなら、推測で調べ始めない — 何が足りないかを述べて戻る。呼び出す側が問いを引数に畳み込むのが正しい使い方である。

1. その問いを **一次情報源** — 公式ドキュメント、ソースコード、仕様、ファーストパーティの API — に対して調査する。それらの二次的な要約ではない。すべての主張を、それを裏付ける情報源までたどる。

2. その発見を1つのマークダウンファイルに書き、各主張の出典を引用する。**長さは問いが必要とする分に合わせる** — 実質を網羅し、埋め草の節・重複した要約・定型句で膨らませない。

3. リポジトリがすでにそうしたメモを保管している場所に保存する。既存の慣習に合わせ、それがなければ適切な場所に置く。

4. 最終メッセージは **書いたファイルのパスと、問いへの答えの要点** に絞る。調査の過程で読んだ内容をここに書き写さない — それはファイルの中にあり、呼び出した側が読み返さないものが親のコンテキストに戻るのは、フォークした意味を打ち消す。
