# 作ったばかりの EmDash サイトを最新に追いつかせる

`create emdash` が落としてくる公式テンプレート([`emdash-cms/templates`](https://github.com/emdash-cms/templates)。既定は Cloudflare 向けのブログ `blog-cloudflare`)は EmDash のリリースごとに同期されるが、同期されるのは **依存の版** であって、コードが新しい API に乗り換わるとは限らない。作った直後のサイトは、`package.json` は最新なのに、コードは数版前の書き方のまま、という状態で始まる(例: 0.38 同期時点の `blog-cloudflare` は、0.37 で変わったアバターの URL を古い形で組んでいる)。

このスキルは、その差を **作った直後に1回だけ** 埋める。何を直すかは [CHECKLIST.md](CHECKLIST.md) にある。

**2度目以降の版上げには使わない。** サイトに手が入ったあとは、テンプレートの書き方を前提にした判定と対応が当てはまらなくなる。

## 前提

- `setup-emdash-site` の手順 4(同梱スキルの差し替え)まで済んでいて、雛形のままのコミットがある。
- まだ本番へデプロイしていない。CHECKLIST.md の「本番」は、最初のデプロイのあとにやることとして持ち帰る。

## 手順

**区切りごとにコミットを1つ作る。** 依存の更新・やることリストの各項目・生成型が1つに混ざると、型チェックやビルドが赤くなったときに、上げた依存と直したコードのどちらが原因か切り分けられない。コミットメッセージはリポジトリの慣習に合わせ(まだ無ければ日本語で「何をしたか」を1行)、本文に対応した版を書く。

### 1. 依存を最新にする

```bash
pnpm install
pnpm up --latest
pnpm why emdash
```

- `emdash`・`@emdash-cms/admin`・`@emdash-cms/cloudflare` が **同じ版** になっているかを見る。
- EmDash 以外が上がって型チェックかビルドが壊れたら、その依存だけテンプレートの版へ戻してよい。戻した理由はコミットメッセージへ。

**完了基準:** `pnpm why emdash` が1つの版だけを出す。`package.json`・`pnpm-lock.yaml` をコミットする。

### 2. やることリストより新しい版の変更履歴を読む

CHECKLIST.md の最新の版と、手順 1 で入った版を比べる。入った版のほうが新しければ、そのあいだの版ごとに変更履歴を読む:

```bash
gh release view emdash@<版> -R emdash-cms/emdash --json body -q .body
gh release view @emdash-cms/cloudflare@<版> -R emdash-cms/emdash --json body -q .body
```

サイトのコードか本番の設定に効く変更を控える(手順 4 で使う)。管理画面だけで完結する機能追加は控えない。同じ版なら、この手順は飛ばす。

### 3. やることリストを全項目判定する

[CHECKLIST.md](CHECKLIST.md) を読む。`blog-cloudflare` から作ったなら、冒頭の表から手を付ける。**版に関係なく全項目を** 上から順に:

1. **判定** を流す。当たらなければ次へ。
2. 当たったら **対応** を行う。
3. **本番** があれば控える。
4. その項目だけでコミットする。1行で済む項目どうし(import の付け替えなど)はまとめてよいが、版をまたいでまとめない。

版で範囲を絞らないのは、雛形の版が何であっても、テンプレートのコードは依存より古いからである。

**完了基準:** 全項目について、「当たらなかった / 対応した / 対応しないと決めた(理由)」を1行ずつ言える。

### 4. リストに無い変更を足す

手順 2 で控えた変更に対応し、**同じ変更を CHECKLIST.md に項目として足す**。次に作るサイトは、履歴を読み直さずに済む。

- 項目は判定・対応・本番の3つで書く。**判定** は、作った直後のサイトで機械的に流せる grep かコマンドにする。
- 足した項目が `blog-cloudflare` にも当たるかを判定し、冒頭の表を更新する(`git clone --depth 1 https://github.com/emdash-cms/templates` をスクラッチに置いて流す)。表の版と日付も、そのとき同期されている版に書き換える。
- CHECKLIST.md は kjfsm/skills にあるので、サイトとは別の PR になる。

### 5. 検証する

1. リポジトリの検証ゲート(型チェック・`pnpm build`)。
2. `pnpm dev` を起動し、生成型 `emdash-env.d.ts` が作り直されたら、それだけでコミットする。
3. 対応した項目のうち画面に出るもの(アバター、テーマ、表、コメント欄)は、dev サーバーでそのページを開いて確かめる。確かめられなかったものは「未確認」として控える。

### 6. 引き継ぐ

`setup-emdash-site` の手順 6 へ戻る。そのとき、次の2つをユーザーに示す:

- 対応した項目の一覧(版つき)と、未確認のもの
- **最初のデプロイのあとにやること:** 手順 3 で控えた「本番」の作業

**完了基準:** 上の2つが示されていて、CHECKLIST.md に足した項目があればその PR も出ている。
