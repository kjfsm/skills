# RESOURCES.md の形式

`RESOURCES.md` は、このトピックについて厳選された信頼できる情報源の集合である。説明のための知識はパラメトリックな推測ではなく、ここから引き出すべきである。知恵は、ここに列挙されたコミュニティから得られる。

## 構造

```md
# {Topic} Resources

## Knowledge

- [Book: _The Science and Practice of Strength Training_ — Zatsiorsky & Kraemer](https://example.com)
  Foundational text on programming and adaptation. Use for: anything to do with periodisation, recovery, intensity zones.
- [Article: "How Much Should I Train?" — Greg Nuckols (Stronger By Science)](https://example.com)
  Evidence-based review of volume landmarks. Use for: weekly set targets per muscle group.

## Wisdom (Communities)

- [r/weightroom](https://reddit.com/r/weightroom)
  High-signal subreddit, moderated against bro-science. Use for: programme critique, plateau troubleshooting.
- Local: Tuesday strength class at {gym name}
  Use for: real-time coaching feedback on lifts.
```

## ルール

- **信頼度の高いものだけ。** 一次情報源、著名な専門家、査読済みの研究、しっかりモデレートされたコミュニティを優先する。あるリソースが教育を装ったマーケティングであれば、除外する。
- **すべてのエントリに注釈を付ける。** 裸のリンクは3か月後には役に立たない。1行を加える: それが何をカバーし、いつ使うべきか。
- **Knowledge / Wisdom でグループ分けする。** [SKILL.md](./SKILL.md) の思想を反映する。あるリソースがどちらか一方のグループにしか現れなくても構わない。
- **ギャップは明示的に表面化させる。** ミッションが必要とする領域に良いリソースがない場合、`## Gaps` セクションを書き、何が欠けているかを列挙する。これが今後の探索を駆動する。
- **容赦なく刈り込む。** 間違っている、浅い、あるいはミッションから外れていると判明したリソースは、埋もれさせるのではなく削除する。凡庸なリソース30個より、鋭いリソース5個の方がよい。
- **コミュニティの好みを記録する。** ユーザーがコミュニティへの参加をオプトアウトしている場合は、今後のセッションで繰り返し提案しないよう、ここに書き留める。
