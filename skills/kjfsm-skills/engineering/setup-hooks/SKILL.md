# フックを敷く

`CLAUDE.md` と `.claude/rules/` は**読まれることを期待する**層である。読まれれば効くが、読まれたかどうかは観測できない。フックはハーネスが実行するので、**モデルが何を読んだかと無関係に効く**。

`/setup-rules` が敷く自己更新ルールの3段目がここに当たる — 1. パス固有の事実は rules、2. 手順は skills、**3. 決定的に弾きたい挙動は hooks**。

**フックは散文の強化版ではない。置き換えである。** 同じことを両方に書くと、フックが黙って壊れた日に散文だけが残り、守られていると誤解したまま進む。フックにしたルールは、散文側では「フックが弾く」という1行に痩せさせる。

これはプロンプト駆動のスキルであり、決定的なスクリプトではない。探索し、見つけたものを提示し、ユーザーと確認し、それから書く。

## 何をフックにするか

**3つすべてを満たすものだけ**を落とす。1つでも欠けたら散文のままにする。

1. **すでに散文で書いてあり、実際に破られた。** 先回りしない。破られていないルールにフックを足すと、コストだけが残る
2. **破られたことに気づけない、または戻すのが高い。** 型エラーや落ちるテストが教えてくれるものには要らない — 生成物の手編集(次の再生成で黙って消える)、保護ブランチへの push(戻せない)、シークレットのコミットが典型
3. **ツールの入力だけで機械的に判定できる。** パスの glob、コマンドの接頭辞。**「適切か」を判断する必要があるなら、フックにはできない** — 判断はモデルの側にしか無い

**通ってよい操作を1つでも止めるフックは、無いより悪い。** 止められたモデルは目的を捨てず、別の経路を探す — `Edit` が弾かれれば `Bash` の `sed` で書く。回避されたぶんだけ、ルールは守られたように見えて実際は緩む。

## 手順

### 1. 探索する

- `CLAUDE.md` / `.claude/rules/` — **すでに書いてある**禁止事項。ここに無いものはまだフックの候補ではない
- `git log` — 実際に破られた痕跡。生成物の手編集を戻すコミット、revert、`main` への直コミット
- `.gitignore` と生成物の実パス、それぞれの再生成コマンド
- `.claude/settings.json` — すでにフックがあるか。あるならマージであって新規作成ではない
- `package.json` の scripts — セッション開始時に要る準備(インストール、生成)
- インストール済みのスキル — git の破壊的コマンドだけが目的なら `/git-guardrails-claude-code` が完成品を持っている

### 2. 候補を挙げ、確認する

候補ごとに、上の3条件を1行ずつ埋める。埋まらないものは落とす。埋まったものを一覧でユーザーに見せ、確認を取ってから書く。

**どのツール経由の操作を止めるかも一緒に決める。** `Edit|Write` だけに掛けたフックは `Bash` の `sed -i` を素通しする。両方を見るか、片方だけと知ったうえでそう決めるかの2択で、**知らずに片方だけ**が最悪である。

### 3. イベントを選ぶ

| やりたいこと                     | イベント       | matcher                         |
| -------------------------------- | -------------- | ------------------------------- |
| 実行前に止める                   | `PreToolUse`   | ツール名(`Bash`、`Edit\|Write`) |
| 書いた直後に検査する             | `PostToolUse`  | ツール名                        |
| セッション開始時に環境を整える   | `SessionStart` | `startup\|resume\|clear`        |
| 応答を終える前に最後の関門を置く | `Stop`         | なし                            |

`SessionStart` の標準出力は**そのままコンテキストに入る**(`UserPromptSubmit` も同じ)。他のイベントの標準出力はデバッグログにしか出ない。

**`Stop` に重いゲートを置かない。** 応答のたびに走るので、型チェック1本(数秒)が上限である。テストや E2E は CI が持つ(`/setup-ci`)。

### 4. 書く

雛形は [recipes.md](./recipes.md) にある。作法は4つ。

**拒否は終了コード 0 と `hookSpecificOutput.permissionDecision: "deny"` で返す。** 終了コード 2 でも今のところ止まるが、そちらは非推奨の経路である。

**判定できなかったら黙って通す。** `jq` が無い、JSON の形が違う — このとき拒否に倒すと、フックが壊れた瞬間に何も実行できなくなる。何も出力せず `exit 0` すれば通常の権限フローへ戻る。

**理由に逃げ道を書く。** `permissionDecisionReason` はモデルがそのまま読む唯一の文字列である。「禁止」だけ書くと迂回を探し始める。**代わりに何をすればよいか**まで書く — 「`app/db/auth-schema.ts` は生成物。`pnpm db:generate` で作り直す」。

**速く保つ。** マッチするツール呼び出しのたびに走る。フック自身がリポジトリ全体を走査すると、その分だけ毎回遅くなる。

### 5. 両方向を検査する

**弾く側だけ試して終えない。** 通す側が壊れているフックは、動いているように見えて作業を止める。

```bash
echo '{"tool_name":"Edit","tool_input":{"file_path":"app/db/auth-schema.ts"}}' | .claude/hooks/<name>.sh
echo '{"tool_name":"Edit","tool_input":{"file_path":"app/db/index.ts"}}' | .claude/hooks/<name>.sh
```

前者は `"permissionDecision":"deny"` を含む JSON、後者は**無出力**で、どちらも終了コード 0 になる。

### 6. 置き場所と越えない線

- **`.claude/settings.json`** — コミットする。リポジトリを clone した全員とクラウドセッションに届く
- **`.claude/settings.local.json`** — 手元だけ。gitignore 済み。端末固有のパスを含むフックはこちら
- **`~/.claude/settings.json`** — 全プロジェクト。ここに置くのはリポジトリに依存しないものだけ

⚠️ **フックはユーザーの権限で走る。** プロジェクトの `.claude/settings.json` のフックは、そのフォルダを信頼する前に走りうる。**リモートから取ってきたものを実行しない**、シークレットを読まない、書き込みをしない。

### 7. 完了

置いたフックと、**それぞれが何を通すか**をユーザーに伝える。散文側で痩せさせた行があればそれも伝える — 二重に書いたままにすると、フックが壊れた日に気づけない。
