# ai-efficiency(大量ファイル移動・リネームの機械的戦略)

変更が **パス・シンボル名の機械的置換に閉じる**(ロジックを変えない)なら、1ファイルずつ Read/Edit せずシェルで一括処理し、抜けの検出は `typecheck` に委ねる。100 ファイル規模で 10〜20 倍のトークンを削れる。設計判断や API の意味変更など中身を理解して書き換える作業は、通常どおり Read→Edit。

移動は `git mv`(履歴を保持)。そのうえで肝は2つ:

1. **置換前に、相対 import を `@/` 絶対へ正規化する。** 相対 import が混ざると一括置換が割れる。正規化してから、末尾 `"` を付けて部分一致を防いで置換する:
   ```bash
   grep -rl '@/old/Name"' app | xargs -r sed -i 's#@/old/Name"#@/new/Name"#g'
   ```
   (普段は `grep`/`sed` より Grep/Read ツールを優先するが、この機械戦略のときだけ一括 `sed` を採用してよい)
2. **検証は `typecheck` に委譲する。** 全ファイルを目視せず、`typecheck` が落とした箇所だけ個別修正する。

## 完了

- [ ] 一括置換後、`typecheck` が green(置換の抜けが残っていない)
