`/mattpocock-skills:to-tickets` に出す切り方の案と、各チケットを `/kjfsm-skills:implement-and-review` で作るときに守ることを置く。game-01(もちずもう)で後から直したものは、ここで最初から入れる。

| #   | チケット                           | ブロッカー |
| --- | ---------------------------------- | ---------- |
| 1   | ひとりで CPU と1勝負できる(曳光弾) | なし       |
| 2   | 数をシミュレーションで決める       | 1          |

## 1. ひとりで CPU と1勝負できる

勝負の計算・部屋の DO・canvas の画面・スマホの操作を、細く一本通す。

- **勝負は、DO にも画面にも依らないクラス(game-01 の `app/game/match.ts`)に入れる。** 乱数は種つきのものを外から渡し、時刻は tick の数から作る。node 層のテストで、勝負を種から再現する
- **式と数は1か所に置く。** 動きの式(加速・衝突・突進)は `physics.ts` に置き、サーバーと手元の予測が同じ関数を呼ぶ。数は `constants.ts` に置く。2か所に書くと両者がずれ、手元の補正が止まらない
- **決着は「残りが1つになった瞬間」に決める。** 落ちきるのを待ってから数えると、押し出した勢いで自分も落ちた側が引き分けになり、先に落ちた側に手柄がつく。手柄は、そのときまだ場に残っている相手にだけつける
- **途中で抜けた人も結果に載せる。** 抜ければ負けが消える形にすると、負けそうになったら抜ければよくなる。ただし、勝ちが決まったあとに勝者が抜けた場合は、勝ちのまま記録する
- **部屋1つを DO 1つにする。** 人がいる間だけ固定の tick で勝負を進め、全員へ配る。守ることは [NETCODE.md](NETCODE.md) の「サーバー」
- **スマホの操作は左右で分ける。** 画面の左半分は、触れた位置を中心にしたスティック。右半分は、どこを叩いてもボタン。`touch-action: none` と safe-area を入れる
- **観測を `docs/agents/verification.md` の観測の行に書く。** Playwright のスクリプトで、iPhone の縦・横と PC の3台を同じ部屋に入れ、スクリーンショットを撮る。以後のチケットでは `/kjfsm-skills:verification-loop` がこれを駆動する。見るのは次の3つ
  - 右上の人数が人の数と合うか(合わなければ幽霊 → NETCODE.md)
  - HUD が盤面やボタンに重ならないか(iPhone SE の縦と、横持ちの低い画面も)
  - 開始・脱落・決着・次の勝負までが一巡するか

  タッチは CDP の `Input.dispatchTouchEvent` で入れる。スクリーンショットに `caret-color` のハイドレーション差分が出ても、Playwright がカーソルを隠すスタイルなので無視してよい

完了: 勝ち・引き分け・手柄・途中で抜けた人の扱いを、種つきのテストで1本ずつ確かめた。bindings 層で DO に WebSocket を張り、welcome・顔ぶれ・状態が届くことを確かめた。

## 2. 数をシミュレーションで決める

CPU 同士の勝負を数百回回すスクリプト(game-01 の `pnpm sim`)を置き、**勝負の長さと一緒に、最初の脱落までの時間を測る。**

もちずもうの最初の値は、勝負の長さこそ平均 16 秒でまずまずに見えた。ところが最初の押し出しは平均 3.8 秒で来ていて、早い回は 2 秒を切っていた。人間が自分のキャラを見つける前に終わる。これを2つの手で直した。

- 反発・突進の重さを下げ、抵抗を上げる
- 出だしの 1.5〜3 秒は CPU に様子見させる

人間が全員抜けたら CPU 同士を早回しする、といった仕組みはシミュレーションでは切る。コンストラクタで倍率を渡せば、共有の定数を書き換えずに済む。

完了: 2つの分布を出した。数を変えたら回すことを、そのリポジトリの `.claude/rules/` に書いた。

## 3. 手触り

自分のキャラは手元で先に動かし、他人は補間して描く。演出と音は、描く時刻に合わせて鳴らす。守ることは [NETCODE.md](NETCODE.md) の「画面」と「スマホの実機まわり」。

完了: 観測で、縦・横・PC の3台が同じ部屋で遊べる。

## 4. 公開の部屋と合言葉の部屋

- **公開の部屋は、満員なら次の部屋へ回す。** `locationHint` で日本の近くに置く
- **合言葉の部屋では、CPU を外して1対1ができる。** 外しても人がひとりなら、CPU を1体だけ呼ぶ
- **同じアカウントで入り直したら、古い接続を閉じる。** 閉じないと、自分のキャラを2つ並べて自分で自分を倒し、点を積める

完了: 満員で断ること、古い接続を閉じることを、bindings 層でテストした。

## 5. ログイン・名前・番付

ログインそのものは `/kjfsm-personal:connect-kjfsm-auth`、開発用の入口は `/kjfsm-skills:dev-bypass-sign-in`、名前と番付は [ACCOUNT.md](ACCOUNT.md)。

完了: 3つを満たした。

- 初回のログインで名前を聞かれる。設定で変えると、トップにも番付にも新しい名前が出る
- 名前の無いアカウントを全ページで `/welcome` へ送り、`/api/auth` と `/login` は通すことを、テストで撃った
- 同点の人が、一覧でも自分の欄でも同じ順位になる
