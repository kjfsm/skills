# ハードな依存関係にだけ、明示的な `/setup-skills` へのポインタを置く

エンジニアリング系スキルは、`/setup-skills` が仕込むリポジトリごとの設定(イシュートラッカー、トリアージラベルの語彙、ドメインドキュメントの配置)に依存している。一部のスキルはその設定なしでは意味のある動作ができない — 特定のイシュートラッカーへ公開したり、特定のラベル文字列を適用したりする必要がある。一方、他のスキルは出力を研ぎ澄ますためだけにそれを使い(語彙、ADR の把握)、なくても穏やかに動作を落とせる。

これらを **ハード依存** スキルと **ソフト依存** スキルに分けている:

- **ハード依存**(`to-tickets`、`to-spec`、`triage`、`wayfinder`、`two-axis-review`) — 明示的な一文を含める: _「… があなたに渡されているはずである — なければ、`/setup-skills` を実行するようユーザーに伝える。」_ その対応付けがなければ、出力は曖昧になるだけでなく間違う。前の3つはイシュートラッカーへ書き込むため、`wayfinder` はマップと子チケットの表現がトラッカーごとに違うため、`two-axis-review` は Spec 軸が元のイシューを読みにいくためである。
- **ソフト依存**(`diagnosing-bugs`、`tdd`、`improve-codebase-architecture`) — 「プロジェクトのドメイン用語集」や「触れている領域の ADR」を、あくまで漠然とした文章で参照するに留める。ドキュメントがそこになくてもスキルは動作する。出力の切れ味が落ちるだけである。

この切り分けにより、ソフト依存のスキルはトークンを節約できるうえ、セットアップへのポインタが本質的でない場所にまで機械的にコピーされるのを避けられる。

## 動詞は「伝える」であって「実行する」ではない

当初この一文は「なければ `/setup-skills` を実行してください」だった。`setup-skills` はモデル呼び出し型なので、字面どおりエージェントが自分で起動できてしまう。

そうさせない。`setup-skills` の中身は **5セクションの対話インタビューと `docs/agents/` への4ファイル新規作成** であり、`/to-spec` や `/triage` の途中でこれが始まると、ユーザーが頼んだ作業が止まってリポジトリのセットアップが始まる。頼まれていない大きな作業であり、`setup-repo` の「工程を先回りして足さない」と同じ線である。

止まらずに進める道があるスキルは、それを先に使う — `wayfinder` はトラッカーが渡されていないときローカルの markdown をデフォルトにする。
