# ブラウザゲームを作る

参考実装は `~/github/kjfsm/game-01`(もちずもう — 土俵で押し出し合う対戦。本番は `https://mochi-sumo.kjfsm.net`)。形に迷ったらそこを開く。

**kjfsm のメインフロー(`/kjfsm-skills:ask-kjfsm`)に沿って進める。** このスキルが足すのは、各段でゲームに固有のことと、game-01 で踏んだ手戻りだけである。

細部は4つのファイルに分けてある。

- チケットの切り方と、各チケットで守ること: [SLICES.md](SLICES.md)
- 通信まわり(DO と画面): [NETCODE.md](NETCODE.md)
- ログイン・名前・番付: [ACCOUNT.md](ACCOUNT.md)
- 本番に出す順: [DEPLOY.md](DEPLOY.md)

手順 1〜4 は、1つの途切れないコンテキストで進める。そのあと、チケットごとにコンテキストを空ける。

`to-spec`・`to-tickets`・`implement-and-review` はユーザー呼び出し型で、モデルからは呼べない。ユーザーに打ってもらうか、その本文(プラグインの SKILL.md)を読んで同じ手順を踏む。

## 1. 何を作るか決める

面白さは作ったあとからは足しにくい。次の4つを満たす案を選ぶ:

- 縦持ちのスマホで、片手の親指で動き、もう片手で1つのボタン
- 1回の勝負が 20〜40 秒。負けてもすぐ次が始まる
- ひとりでも遊べる(人が足りなければ CPU が埋める)。友だちとは合言葉の部屋で遊び、そこでは CPU を外して1対1もできる
- 決着の瞬間に名前が付く(もちずもうなら決まり手)。演出と実況の種になる

ユーザーが「任せる」と言っていれば、自分で決める。自分で決めたいなら、土台を起こしたあとに `/mattpocock-skills:grill-with-docs` で詰める。どちらの場合も、決めた語は `CONTEXT.md` に置く。

完了基準: 遊び方を1文で言えて、4つとも満たす。

## 2. 土台を起こす

`cf-workers-full-stack-template` から起こす。kjfsm-auth の RP と共有 D1 の相乗りが組み込み済みで、`/kjfsm-skills:setup-repo` が敷くもの(検証ゲート・rules・CI・lefthook・イシュートラッカーの設定)もそろっている。手順はテンプレートの README「フォークしたら」が持つ。そこに無い落とし穴:

- 手元の clone は古いことがある。`git fetch` してから `git archive origin/main | tar -x -C <新しいリポジトリ>` で写す
- テンプレートの `kjfsm/cf-workers-full-stack-template#11` より前の版から起こした場合は、次の2つを踏む
  - README の置き換え手順が `git grep` になっている。写した直後はファイルが未追跡なので、何も拾わない。`grep -r --exclude-dir=node_modules` を使う
  - origin/main に `wrangler.jsonc` がまだ無く、`check:migrations` が `git show` で落ちる。#11 の `existsAt` の形で直す
- 手元のポートは `grep -rhoE 'port: ?[0-9]{4}' ~/github/kjfsm/*/vite.config.ts` で空きを探す
- `.gitignore` に `.claude/worktrees/` を足す。テンプレートには無く、本体のチェックアウトで worktree が未追跡に出る

完了基準: 名前・slug・ポートを置き換え、テンプレートの検証ゲートが緑のままコミットした。

## 3. 仕様にする — `/mattpocock-skills:to-spec`

次の決定は、game-01 で公開したあとやレビューで直したものである。最初から仕様に入れる。

- 決着は、残りが1つになった瞬間に決める。手柄は、そのとき場に残っている相手につける
- 途中で抜けた人は負けとして載せる(勝ちが決まったあとの勝者は勝ち)
- 同じアカウントが入り直したら、古い接続を閉じる
- 合言葉の部屋では、CPU を外せる
- ログインのボタンは「Google でログイン」
- 名前はアカウントに持つ。IdP の名前は使わず、初回のログインで聞き、設定で変えられる
- 番付の同点は同じ順位にする
- 本番は、main にマージしたあと人間が繋ぐ Workers Builds が出す

テストのシームは4つ。

- 勝負の計算: node 層
- 部屋の DO: bindings 層で WebSocket を張る
- ページと関所: http 層
- 画面: E2E と、Playwright で3台を駆動する観測

完了基準: 仕様がイシューとして出て、上の決定とシームが載っている。

## 4. チケットに分ける — `/mattpocock-skills:to-tickets`

[SLICES.md](SLICES.md) の切り方を叩き台にする。最初は、ひとりで CPU と1勝負できる曳光弾。

完了基準: チケットがブロッキングエッジ付きで出た。

## 5. チケットごとに作る — `/kjfsm-skills:implement-and-review`

ブロッカーの片付いたチケットから1本ずつ作る。各チケットで守ることは [SLICES.md](SLICES.md) の同じ番号の節にあり、完了基準もそこにある。

完了基準: 本番に出すチケットを残して、すべての PR がマージされた。

## 6. 全体を二軸レビューする — `/kjfsm-skills:two-axis-review`

基点は、テンプレートから起こしたコミット。スペックは、ユーザーの依頼文と手順 3 の仕様。チケットごとのレビューでは、ファイルをまたぐずれや、あとのチケットが先の約束を崩したものは見えない。

完了基準: 両軸の指摘を直したか、直さない理由を持った。

## 7. 本番に出す

**エージェントは本番へ手でデプロイしない。** 本番は、main への push を受けた Workers Builds が出す。その連携は、main にマージしたあと人間が繋ぐ。順序は [DEPLOY.md](DEPLOY.md) にある。人間の手順は `/mattpocock-skills:wizard` で台本にしてよい。

完了基準: 次の3つを満たした。

- 最初のビルドが、マイグレーションとデプロイを通した
- 本番の URL で、2台が同じ部屋に入れた
- IdP の認可エンドポイントが、クライアントを受け付けた

実機での確認と、IdP を通したログインの一巡は人間に渡した。
