# ログインと名前

game-01(もちずもう)で、公開したあとにユーザーから直された形。ログインそのもの(RP の組み方・ボタンの文言)は `/kjfsm-personal:connect-kjfsm-auth` を見る。

## 名前の置き場所

- **ログインした人の名前は、アプリ側のテーブル(`<slug>_profile`)にアカウントごと1つ持つ。** IdP の `user.name` は使わない
- **ゲストの名前は端末(localStorage)に持つ。** サーバーで描かれる部品では `useSyncExternalStore` で読む(→ NETCODE.md)
- **名前の入力欄は `autoComplete="off"` にする。** `name="name"` の欄には、ブラウザが氏名(本名)の自動入力を差し出す

## 初回のログインで聞く

関所は root の middleware の1か所に置く。middleware は、アカウントを要求ごとに1回だけ引いて context に置く。名前の無いアカウントは、どのページを開いても `/welcome?redirectTo=<元のパス>` へ送る。

- **`/welcome`・`/login`・`/api/*` は通す。** `/api/` まで止めると、ログアウトもできなくなる
- **loader ごとに判定を書かない。** 写し忘れたページ(game-01 では番付)が、ビルドもテストも通ったまま素通りになる
- **ログインの戻り先(`callbackURL`)は元のページのままでよい。** 戻った直後の要求を middleware が捕まえる
- **`/welcome` は、ページ自身の middleware でログインを要求する。** loader と action に同じ判定を2回書かない
- **テストは、名前の無いアカウントで全ページぶん「送られる」を撃つ。** あわせて、`/api/auth` が通ることも撃つ(開発用の入口に、名前を決めない種の人を1人用意する)

## 変えられるようにする

- **設定画面(`/settings`)で変えられるようにする。** ゲストは同じ画面で、端末の名前を変える
- **番付は、名前を `coalesce(profile.name, stats.name)` で読む。** 取組の結果は、土俵が入室時に持った名前で書かれる。そのため stats の名前だけを見ていると、名前を変える前から開いていたタブの取組が終わった時点で、番付が古い名前に戻る
- **土俵(DO)へは、アカウントの名前を Worker からヘッダで渡す。** 手元から送られた名前は、ゲストのときだけ使う。日本語はヘッダにそのまま載らないので、`encodeURIComponent` して載せる
